# Единый формат игровой энциклопедии

Формат `race-1` сочетает обычную энциклопедическую статью в Markdown с небольшим формальным слоем. Факты, объяснения и причинные связи остаются связной прозой. Таблицы используются для карточек, хронологии и сравнения, списки — для перечислений.

## Статус внедрения

Эталон: [Дейми](race_deymi.md), `race.deymi`. Все 19 актуальных досье рас переведены на Markdown и схему `race-1`. Все 8 общих справочников переведены на Markdown и схему `reference-1`. В текстовом формате `legacy-text` остаются 4 досье персонажей, отдельная планетология и игровое приложение. Архивные статьи, концепты и редакционные материалы не включены в каталог текущего канона. Сам формат не означает, что все факты прошли содержательную сверку.

## Метаданные документа

В начале файла находится плоский YAML-блок. Чтобы не зависеть от библиотек и неоднозначных преобразований YAML, допускаются только перечисленные ключи и строки в двойных кавычках по правилам JSON (это совместимый поднабор YAML). Вложенные объекты, даты YAML, дубликаты ключей и некавыченные значения не допускаются.

```yaml
---
id: "race.deymi"
type: "race"
title: "Дейми"
schema: "race-1"
status: "canonical"
---
```

`id` постоянен и не зависит от пути или названия. `canonical` означает принадлежность к текущему корпусу, а не завершённость аудита. `draft` обозначает черновик. Версии текста хранит Git, версия схемы хранится в `schema`. Суффикс версии в имени нового досье не нужен.

## Иерархия и постоянные адреса

- `#` — название статьи, один раз.
- `##` — основные разделы I–XVII и визуальное приложение.
- `###` — стандартные подпункты и блоки межрасовых отношений.
- `####` — детали подпунктов; более глубокие уровни не используются.

Перед каждым заголовком, кроме названия статьи, стоят явный HTML-якорь и комментарий статуса. В отображаемой статье эти две строки скрыты, но остаются доступны любому текстовому парсеру.

```markdown
<a id="biology.reproduction"></a>
<!-- section-status: filled -->

### III.12. Система размножения

Описание размножения связной прозой.
```

Адрес раздела: `race.deymi#biology.reproduction`; обычная ссылка внутри статьи: `[III.12](#biology.reproduction)`. Постоянные адреса общих разделов заданы в [схеме](schemas/race-1.json), а не вычисляются из заголовка. Идентификатор однажды созданного нестандартного подраздела также сохраняется при переименовании. Идентификаторы уникальны внутри документа.

Римские номера сохраняют существующие смысловые слоты. Нельзя перенумеровать оставшиеся пункты после удаления неприменимого раздела. Для небиологических рас предусмотрена альтернатива `architecture`, закрывающая III и III.1–III.19. Если исходная статья сохраняет основной заголовок III с пояснением неприменимости биологии, архитектура вкладывается в него на один уровень ниже и закрывает только III.1–III.19, не дублируя сам слот III. Детали глубже четвёртого уровня отображаются заголовками четвёртого уровня; полный смысловой адрес сохраняется в ID. Диапазонное закрытие, например XIV–XVI, занимает все указанные слоты, не создавая дублирующих разделов.

## Статусы разделов

| Машинное значение | Смысл | Что видит читатель |
|---|---|---|
| `filled` | Есть описание темы; не гарантия полноты или проверки фактов | Обычный текст |
| `not_applicable` | Раздел неприменим | Объяснение причины и при необходимости ссылка |
| `unknown_in_canon` | Неизвестность является фактом сеттинга | Что именно неизвестно и кому |
| `needs_development` | Редакционный пробел | Явное «требует разработки» с пояснением |

Для трёх последних статусов обязательна понятная фраза в видимом тексте. Нельзя объявлять неизвестным в каноне то, что автор просто ещё не написал. Если тема заполнена частично, сохраняется `filled`, а конкретные пробелы обозначаются в тексте.

## Источники и повторение фактов

Приоритет источников установлен в [оглавлении](README.md#приоритет-источников). Параметры миров принадлежат справочнику систем, общая история — хронологии, особенности расы — профильному досье. Ссылки на конкретные разделы предпочтительнее ссылок на весь файл.

Для удобства чтения допустима краткая сводка в карточке расы, но она не становится независимым источником. При конфликте источников одного уровня фиксируются обе версии и вопрос автору. Машинное совпадение дат само по себе не подтверждает канон. Реестры контактов и эпох ещё не созданы; каталог не заменяет их.

## Каталог и работа скриптов

[catalog.json](catalog.json) автоматически собирается из текущих статей в корне `GameDoc`. Каталог содержит `id`, путь, тип, статус, формат, схему, старые пути (`aliases`), адреса и диапазоны строк разделов. Полный текст и отдельные канонические числа туда не копируются. У legacy-разделов статус `null`: скрипт не угадывает его по словам в тексте. `slot.*` — временный адрес нестандартного legacy-раздела до его миграции.

Каталог генерируется детерминированно, без времени генерации. Вручную его не редактируют. Старые пути задаются в [document-aliases.json](schemas/document-aliases.json). Старые пути всех 19 досье и 8 справочников разрешаются через aliases; вторых копий статей с устаревшим текстом нет.

Команды из корня репозитория (Python 3, без внешних зависимостей):

```bash
python tools/docs/lore_format.py validate
python tools/docs/lore_format.py index
python tools/docs/lore_format.py index --check
python tools/docs/lore_format.py section race.deymi#biology.reproduction
python tools/docs/lore_format.py section race.deymi#history.episodes.steel-crisis
python tools/docs/lore_format.py search "размножение" --section III.12
python tools/docs/check_lore_structure.py
```

Поиск по фиксированному номеру или общему ID работает и в поддерживаемых legacy-разделах. Поиск читает сами статьи, а не устаревшую копию каталога. Проверка `index --check` обнаруживает рассинхронизацию сохранённого каталога.

## Перенос следующей статьи

1. Сверить исходный файл с текущим списком досье; не брать файл из архива.
2. Перенести текст в Markdown, сохранив все факты и смысловые слоты.
3. Добавить метаданные, стандартные адреса из схемы и постоянные адреса собственных подразделов.
4. Явно обозначить редакционные пробелы; не заполнять их выдуманными фактами.
5. Обновить ссылки оглавления и alias старого пути. Старый файл удалить из текущего корпуса; история останется в Git.
6. Проверить сохранность текста, структуру, ссылки и чтение выбранного раздела; пересобрать каталог.

## Редакционные пробелы, выявленные при переносе

В досье ИИ Древних явно обозначен ранее не выделенный диапазон IV.1–IV.11. В досье Спасителей обозначен отсутствовавший IV.10. Они имеют статус `needs_development`; это редакционные пометки без добавления канонических фактов.

Автоматические внутренние ссылки не подставляются вместо ссылок на другую статью: упоминание чужого названия или общего справочника сохраняет исходный контекст источника.

## Общие справочники: reference-1

[Схема reference-1](schemas/reference-1.json) использует те же плоские метаданные, уровни заголовков, явные якоря и статусы. Тип документа — `reference`; его постоянный ID сохраняется из каталога, например `reference.gipersfera`. Структура свободная: справочник не обязан содержать разделы I–XVII досье расы.

Исходные номера и дополнения, включая `I.2-доп` и `III.4-ранн`, сохраняются как `labels` разделов в каталоге. Они не смешиваются с фиксированными слотами рас. Постоянный адрес может быть смысловым: `reference.gipersfera#theory.holding-field`. Команда `section` понимает как этот адрес, так и `reference.gipersfera#I.2-доп`. При поиске по номеру нужно учитывать, что один и тот же номер в разных документах имеет разный смысл.

Примеры:

```bash
python tools/docs/lore_format.py section reference.gipersfera#theory.definition
python tools/docs/lore_format.py section reference.gipersfera#I.2-доп
python tools/docs/lore_format.py section reference.spravochnik_sistem#elder-races
```

Оригиналы 8 справочников сохранены без изменения байтов в [архиве](archive/pre_markdown_references/README.md). Преобразование не пересматривает канонические факты, формулы, параметры миров или приоритет источников. Разделы с пометкой «вне канона» или «для дальнейшей разработки» сохраняют эту пометку; принадлежность файла к корпусу не означает принятия каждого предложения внутри него.
