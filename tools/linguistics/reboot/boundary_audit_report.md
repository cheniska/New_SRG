# Аудит грамматики: стыки морфем и омонимия

**Статус:** проверка лабораторной морфологии `morphology_v2.py`; не утверждает суффиксы, приставки и формы в лоре. Результаты машинной проверки на текущей экспериментальной таблице, не оценка человеческого/синаптского слуха.

## Как различать слово и синтаксис

- `цвэк-и-дзрим-ац` = лексически оформленный сложный термин «детектор сигналов». Можно хранить в словаре как **одно** слово.
- `цвэкидзримац-эц` = тот же термин **в местном падеже**, то есть «в детекторе сигналов», в конкретной фразе.
- Отдельный корень «место» **не добавляется**. Суффикс словообразования «место действия» `-ор` допустим только когда хотим *назвать самостоятельный тип места*, например специально устроенный наблюдательный пост. Грамматический местный падеж -эц с ним не равнозначен.
- Прочие члены предложения — отдельные слова, если их сочетание не стало устойчивым лексическим понятием.

## Реальный размер таблицы

По текущему каталогу: 12 корней × **10** словообразовательных вариантов × **3** числа × **9** падежей = **3240 форм существительных**. Раннее указание 720 относилось к прежнему меньшему каталогу, не к нынешнему набору.

Глагольные формы: 12 корней × 3 времени × 7 видов/акциональностей × 2 полярности × 4 наклонения = **2016 форм**.

Контрольное перечисление по структуре текущих таблиц даёт 3240 уникальных строк для существительных и 2016 уникальных строк для глаголов, **без буквальных дубликатов внутри каждой группы**. Это не исключает омонимов между существительными и глаголами или в большем словаре.

## Проблемы на стыках

По перечислению 3240 существительных, **учитывая все повторения форм парадигмы**:

- **117 стыков** одинаковых согласных, например `цвэк-ик-к` → `цвэкикк`.
- **204 стыка** двух гласных, например `мцэр-э-эс` → `мцэрээc` (последний символ кириллический `с`, форма показывает зияние).
- Для этих форм текущий грубый анализ не выявил стыков >3 согласных фонем или соседних аффрикат **именно на границах словообразовательных/грамматических суффиксов**. Другие проблемы в корнях остаются возможны.

Эти числа — **количество случаев**, а не число уникальных слов с проблемой. Они не обозначают частотность в живой речи.

## Варианты разрешения, пока не утверждены

| Проблема | Предлагаемый вариант A | Альтернатива B | Примечание |
|---|---|---|---|
| Двойная согласная на стыке | Удвоение произносится как долгий согласный | Вставка короткого `э` | Удалять одну согласную опасно: может стереть границу морфем |
| Две гласные на стыке | Сохранять обе, допустив зияние | Вставка переходного `й` | Декоративные апострофы не нужны |
| Слишком длинный кластер | Вставлять `э` по формальному условию | Ограничить допустимые суффиксы | Не менять все стыки вручную |
| Совпадающие формы разных категорий | Проверять по части речи и синтаксису | Переименовать маркер | Для языка допустима омонимия, но не повальная неразличимость |

**Приоритет:** сперва выбрать фонотактику и проверить реальные предложения, затем вводить автоматические звуковые изменения. Все результаты должны хранить исходные морфемы, чтобы изменение произношения не уничтожало обратный разбор.

## Программная проверка

- [morph_boundary_audit.py](morph_boundary_audit.py): перечисляет формы, считает омонимы, проверяет стыки по условным фонемным единицам, сохраняет примеры проблем.
- [test_morph_boundary_audit.py](test_morph_boundary_audit.py): тестирует зияние, удвоения, скопления аффрикат, сохранение контекста и размеры парадигм.

Запуск:
```bash
cd tools/linguistics/reboot
python morph_boundary_audit.py
python -m unittest test_morph_boundary_audit.py -v
```

Проверка допустимости звучания пока эвристическая. Не считать все формы удачными лишь потому, что они прошли программную проверку.
