0. КРАТКОЕ РЕЗЮМЕ
================================================================================
Снаряды (TMissile / TCustomMissile) НЕ используют ship.RouteFilm и НЕ строят
A* план. Каждый кадр TStar_NextDay вызывает TMissile_StepDay (0x5E6D4C),
который выполняет ОДНО элементарное движение:

  (1) При первом тике (age==0): инициализация ОК-1 раз скорости и стартового
      "наследства" вращения от Owner.RouteFilm (имитация инерции пушки).
  (2) Каждый кадр:
        — старение (age += 200/DayFrames);
        — если age < 200: летит ПРЯМО, плавно подгоняя угол под Owner.Angle
          (если есть Owner) — фаза "разгона из дула";
        — если age >= 200: фаза трекинга. Перечитывается target.Pos
          (TShip/TItem/TAsteroid/TMissile) и берётся угол к нему.
          Если |angle_diff| > 3°/кадр — поворот на 3°; иначе — мгновенный
          захват угла.
        — разгон/торможение скорости: |speed - max| > 10 → ±10 за кадр;
        — движение по углу: pos += dir(angle) * (speed/200 * v61).
  (3) Тест попадания (Capsule-vs-Point, sub_8721B0):
        — radii: 10.0 для предметов/астероидов/прочих missile;
                 20.0 для целевого корабля (10.0, если это Owner);
        — проверяется по 4 спискам в TStar: missiles, ?, ships, asteroids.
  (4) Эвтаназия:
        — age > 1000 или (есть target И age*scale*max_speed > target.dist):
          missile.dead = 1.

Ключевое отличие от ship.RouteFilm-системы:
  • снаряд решает курс ПОКАДРОВО, без планирования вперёд;
  • снаряд читает АКТУАЛЬНУЮ позицию цели каждый кадр (true tracking);
  • цель может теряться и переключаться (sub_5E7E28).

================================================================================
4. АВТОМАТИЧЕСКИЙ ВЫБОР ЦЕЛИ — TMissile_TryReacquireTarget (sub_5E7E28)
================================================================================
Срабатывает каждый кадр после Age >= 200. Алгоритм:

  if  (missile.WeaponType_byte_at_+53 == 5         // homing-class only
       && missile.Owner != NULL
       && (missile.Target == NULL || missile.Target == missile.Owner))
  {
      // ищем ближайшего врага в текущей звезде
      best_dist2 = 1.0e30
      best_ptr   = NULL
      for each Ship in Star.ShipList @ Star+44:
          if  ! ShipIsDead(Ship)
              && Ship != missile.PrevTarget
              && Ship_GetRelationToPlayer(Ship, Owner) == 0   // = hostile
              && (Owner is not TKling
                  || (Ship not in Owner.SpawnedMinions
                      && Owner not in Ship.SpawnedMinions))
          {
              d2 = Dist²(missile.Pos, Ship.Pos)
              if  d2 <= 700.0 && d2 < best_dist2:
                  best_dist2 = d2; best_ptr = Ship
          }
      if  best_ptr:
          missile.Target = best_ptr
      else if  Owner_can_act && Owner.CurStar == missile.CurStar:
          missile.Target = Owner                  // ★ fall-back на Owner!
      else:
          missile.Target = NULL
  }

Замечания:
  • Условие `WeaponType_byte_at_+53 == 5` означает, что переключение
    цели работает ТОЛЬКО для одного типа оружия. Точная семантика
    этого байта (вероятно, weapon-class enum со значением 5 =
    «homing») должна быть подтверждена через Items.txt.
  • Игнорирует Klig-minions Owner'а — чтобы Doppelganger не стрелял
    в свою свиту.
  • Радиус поиска = sqrt(700) ≈ 26.5 единиц. Маленькое окно, так что
    «потеря цели» — частый случай.
  • Если есть Owner, но врагов рядом нет → цель переключается на
    самого Owner'а; в TMissile_StepDay затем сработает sub_5E7BEC
    («self-hit») чтобы либо игнорировать, либо взорваться.

5. RAW-SPAWN ВЕТКА (SE_SpawnMissile)
================================================================================
Script-функция `Missile.Spawn(angle, x, y, speed, ...)` создаёт
TMissile через sub_5E5AB4:

  missile = TMissile.Create(VMT_TMissile)
  TList_Add(Star.MissileList, missile)
  missile.CurStar    = day_step (NB! параметр a2 — на самом деле просто
                                  передан в этом слоте)
  missile.Owner      = NULL                       // ★ без Owner
  missile.Target     = a3 (Star)                  // !!! записан как target
  missile.Pos        = (a11, a12)                 // прямо заданы
  missile.Angle      = a10                        // явный угол
  missile.Speed_max  = a7                         // явная скорость
  missile.MinDamage  = a9
  missile.MaxDamage  = a8
  missile.WeaponId   = 0
  missile.WeaponType = a6
  missile.Field4_4C  = 1
  missile.ShotIndex  = 0

В StepDay при Age < 200 «no-owner» ветка ведёт по straight line.
А при Age >= 200 ветка трекинга срабатывает, если кто-то снаружи
успеет записать missile.Target. Без owner sub_5E7E28 ничего не делает
(там require Owner), поэтому raw-spawn полёт = строго прямой.

Если скрипт хочет «homing raw missile», ему нужно вручную записать
missile.Target ДО кадра 200.

================================================================================
SE_FireWeapon_ProcessMissile (0x7090B0) — основной вход боевого огня
ракетным оружием (вызывается из TStar_NextDay при ход-по-ходу-CombatRound).
Алгоритм (сжато):
  shotCount = TWeapon_ShotCount(weapon)
  for i in 0..shotCount-1:
      missile = TMissile.Create(VMT_TMissile or VMT_TCustomMissile)
      TMissile.Init(missile, owner.CurStar, owner, i, target, weapon)
      // спред уже учтён внутри Init (см. §2.1)
      TShip_ProcessMissileHit(owner, 2 /*event*/, missile, 0, target)

SE_LaunchMissile (script-fn 0x65098C) — то же, но из скрипта; один
залп, один shot_index = arg4 (по умолчанию 0).

8. ЧИСЛЕННЫЕ ПАРАМЕТРЫ
================================================================================
  Tracking activation threshold  : 200 кадров (= 1 игровой ход)
  Pre-tracking angle alignment   : ±0.5°/кадр  под Owner.Angle
  Homing turn rate               : 3.0°/кадр   к target (× v61)
  Speed ramp                     : ±10/кадр    к Speed_max
  Frame normalization v61        : 200 / Star.DayFrames (обычно 1.0)
  Owner-velocity inheritance     : sum(Dist2 over Owner.RouteFilm)
                                    + 100, clamp >= 200
  TryReacquireTarget radius²     : 700 (≈26.5 units)
  Hit capsule radius (ships)     : 20.0 (10.0 для self-Owner)
  Hit capsule radius (others)    : 10.0
  Initial LastDistSq sentinel    : 1621981420 (≈1.85e20 float)
  Max age before forced expire   : 1000 кадров (= 5 ходов)
  Spread fan total               : 60.0° / (shotCount+3) на каждый
                                    индекс, чередуя ±
  Spread spawn offset            : 8.0 единиц вдоль угла

9. КЛЮЧЕВЫЕ ВЫВОДЫ
================================================================================

  1. Снаряды НЕ используют ship.RouteFilm и НЕ планируют путь A*.
     Это отдельная per-frame система с прямым numeric integration.

  2. Снаряд видит АКТУАЛЬНУЮ позицию цели каждый кадр, в отличие от
     корабля (который снимает target.Pos один раз за ход в CalcRoute).
     Поэтому снаряд "догоняет" движущуюся цель естественно.

  3. Поворот ограничен 3°/кадр — это и есть «дальность тактического
     ухода»: если цель крутится быстрее, чем missile может поворачивать
     за время преодоления расстояния, она уйдёт.

  4. Механизм MissJitterCnt — встроенная вероятность промаха:
     если миссайл стал отдаляться от цели (т.е. перелетел), он
     ВКЛЮЧАЕТ jitter на (Speed_max/10..Speed_max/40) кадров. В этой
     фазе sign = +1, что инвертирует Y-дельту в atan2 → миссайл
     летит в зеркально-инвертированном направлении. Это работает
     как «петля промахнувшейся ракеты». По истечении jitter снова
     включается tracking.

  5. Автозамена цели (sub_5E7E28) — только для оружия класса 5.
     В остальных случаях missile.Target фиксирован.
     Когда цель уничтожается или исчезает, missile.Target := NULL,
     и снаряд продолжает по своему углу до expire.

  6. Скорость определяется типом оружия + skill пилота (через
     PortionInDiapason). Никакой явной «дистанции выстрела» нет —
     дальность задаётся произведением Speed_max × (1000 кадров).

  7. Veer/spread залпа: первый снаряд по центру (shotIndex=0),
     дальнейшие чередуют ±60°/(N+3) с инкрементом ±, плюс смещение
     starting Pos на 8 единиц вдоль угла. Так получаются веерные
     залпы Tracker-IBM.

  8. Снаряд считает попадание по СЕГМЕНТУ движения (capsule swept),
     а не точечной позиции — поэтому быстрые ракеты не «проскакивают»
     цели между кадрами.

  9. Raw-spawn missile (без Owner) — это для скриптовых событий
     (метеориты, спец-эффекты). Не трекает цель автоматически;
     для homing нужно вручную записать missile.Target из скрипта.

  10. Графический эффект (TWeaponSE + GFilm) создаётся лишь при
      «is_visible» — для невидимых ракет (вне PlayerStar) обработка
      чисто симуляционная, без расхода GPU.

10. СВЯЗЬ СО Ship_Trajectory_*  ARTICLES
================================================================================
  • Корабли строят план НА ХОД (CalcRoute @ 0x7219B0): target.Pos
    считывается ОДИН раз, далее A* + RouteFilm.
  • Снаряды решают курс ПОКАДРОВО (StepDay @ 0x5E6D4C): target.Pos
    считывается КАЖДЫЙ кадр, угол подстраивается на 3°.
  • Корабль FOLLOW_SHIP получает «упреждённую» точку через leader.RouteFilm
    (waypoint в кадре a4-1). Снаряд УПРЕЖДЕНИЯ НЕ ДЕЛАЕТ — он просто
    бежит за текущей позицией. Это и есть причина того, что быстрая
    цель крутясь может «вечно» уходить от tracking-снаряда: радиус
    поворота × дистанция-в-кадрах должен покрыть тангенциальный обгон.
  • RouteFilm движущегося Owner'а влияет на МОМЕНТ ВЫСТРЕЛА (FirstFrameInit
    суммирует расстояния по плёнке + базу 100) — это симулирует "инерцию"
    пушки, чтобы выстрел из быстро летящего ranger'а не отставал.
  • Hit-test использует CAPSULE-vs-POINT (sub_8721B0) — тот же примитив,
    что мог бы пригодиться в Ship_PlanPath для check-segment, но
    реальный ship-планировщик использует другую функцию sub_872390
    (segment-vs-CIRCLE) — это не одно и то же.

  [ ] Точная семантика missile[+0x4C] WeaponType_byte_+53 — где
      определён enum «5 = homing»? Скорее всего в Items.txt или
      gItemDB-структуре.
  [ ] sub_5E7BEC (self-hit handler) — что именно делает,  возвращая
      bool? Игнорирует Owner, либо вызывает урон самому себе?
  [ ] Магические Extended-константы в проверке expire (Age*const*
      Speed_max < dist): какие реальные коэффициенты? Декомпиле
      показывает -4.95e-136 — скорее всего это 1/(Speed_max × ...).
  [ ] sub_4D8058 — точная семантика «sum Dist2 over RouteFilm».
      Похоже на «total path length», но a2 (второй параметр) в
      контексте StepDay → передаётся уже искажённое scratch-значение.
      Возможно, в живой игре это всегда (0,0) или Owner.Pos.
  [ ] missile[+0x70] MissJitterCnt: правда ли это «промах»?
      Альтернативная гипотеза — это «временный override на ручное
      управление» из скрипта (например, для cinematic-моментов).
      Декомпиляция говорит «при отдалении от цели запускается
      jitter» — это совпадает с поведением промаха.
  [ ] Owner[+196] — что это? В Init читается как initial-speed-candidate.
      Возможно, ship's «engine power» или «hull mass».
