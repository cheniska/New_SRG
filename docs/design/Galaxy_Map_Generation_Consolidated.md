## 1. ОБЩИЙ ОБЗОР ПРОЦЕССА

```text
Генерация галактической карты запускается из потока TThreadCreateNewGame_Execute.
Последовательность верхнего уровня:

  1) TGalaxy_Create              — создание объекта TGalaxy, инициализация списков
  2) TGalaxy_GenerateConstellationsAndStars — главная функция генерации
     Внутри неё:
       a) Создание N объектов TConstellation (секторов)
       b) Вычисление средней площади сектора
       c) Создание полигональной карты (Polygon2D) для пространственного деления
       d) Расстановка центров секторов (8 «расовых» + остальные рандомные)
       e) Назначение звёзд секторам (TGalaxy_AssignStarsToConstellations)
       f) Построение списков звёздных расстояний (TGalaxy_BuildStarDistLists)
       g) Проведение границ секторов (TGalaxy_BuildSectorBoundary)
       h) Расстановка звёзд на координаты внутри секторов
       i) Валидация: проверка минимальных расстояний, связности
       j) При неудаче — повтор (до 1000 итераций для шага d, до 50 для шага h)
  3) MB_Galaxy_setup             — дальнейшая инициализация (планеты, NPC, и т.д.)
```

## 2. СОЗДАНИЕ ОБЪЕКТА TGalaxy И ИНИЦИАЛИЗАЦИЯ

```text
Функция: TGalaxy_Create (адрес 0x839198)

Создаёт экземпляр TGalaxy. Из заметных вспомогательных вызовов:
  - WStr_ParseBool (0x8390A0) — generic «Yes/yes/True/true/TRUE/1» → bool.
                            В TGalaxy_Create используется при обработке блока
                            BV/CheatsDisabled (раньше ошибочно описано как «init»).
  - AntiTamper_FileSizeCheck (0x838FF0) — открывает файл по переданному имени,
                            проверяет (12345678 - FileSize) против переданного
                            magic-числа; результат пишется в gvar_00882098
                            (с разными диапазонами для match/mismatch).
  - TGalaxy_RegisterTableEntry (0x847554) — регистрирует TGalaxy в центральной
                            таблице *gvar_00882218 с ключом (GenSeed XOR a2).
                            Внутри использует sub_4BA768 (alloc + insert под
                            critical section). Все 5 callers — TGalaxy-контексты.
  - TGalaxy_ClearMessageList (0x80770C) — чистит global linked-list TMessagePlayer
                            объектов: g_MessageListHead (88BFD8) / g_MessageListTail
                            (88BFDC). Этот список наполняется через
                            TGalaxy_PostMessage и ищется через TGalaxy_FindObjectByKey.

Поля TGalaxy, участвующие в генерации:
  +0x02C  stars         — TList* (список звёзд TStar)
  +0x160  GalaxyFlags   — uint32_t (имя поля в IDA-структуре TGalaxy).
                          Семантически используется как «количество секторов»:
                          ХАРДКОД = 20 (0x14), устанавливается в TGalaxy_Create
                          (`v83->GalaxyFlags = 20;`) и затем читается как loop
                          counter в TGalaxy_GenerateConstellationsAndStars при
                          создании TConstellation. НЕ читается из конфига.
                          Из конфига берётся только количество звёзд
                          (Constellations.GalaxyCountStars = 73).
  +0x164  Constellations — TList* (список секторов TConstellation)
  +0x168  ConstellationCount — в IDA-структуре объявлено как uint32_t, но
                          фактически в TGalaxy_BuildStarDistLists это поле
                          используется как TList* (доступ через VMT и +8.Count) —
                          список граничных отрезков между секторами. Тип в
                          IDA-структуре требует исправления на TList*.
  +0x058  gen_seed      — сид генерации
  +0x05C  rnd_seed      — текущий сид рандома

Глобальные переменные, влияющие на размер карты:
  off_8828C4 → ширина карты (MapSizeX, default 145, "Constellations.GalaxySizeX")
  off_8823E4 → высота карты (MapSizeY, default 100, "Constellations.GalaxySizeY")
  off_882F10 → кол-во звёзд (default 73, "Constellations.GalaxyCountStars")
```

## 3. ГЛАВНАЯ ФУНКЦИЯ: TGalaxy_GenerateConstellationsAndStars

```text
Адрес: 0x84FF74
Сигнатура: int __usercall (TGalaxy* @<eax>, uint8_t player_race @<dl>)

Параметр dl — раса игрока, используется для определения стартового сектора.

--- 3.1. Создание секторов ---

Первый цикл создаёт TGalaxy.GalaxyFlags (= 20) объектов TConstellation:

    for i = 1 to 20:   // GalaxyFlags (+0x160) = 0x14, hardcoded in TGalaxy_Create
        con = TConstellation_Create()
        Galaxy.constellations.Add(con)

Итого 20 секторов, которые делятся на три группы:
  - Секторы 0..7  (8 шт) — «расовые», центры привязаны к периметру карты.
                            Игрок стартует на планете своей расы в одном из этих
                            секторов (определяется в TThreadCreateNewGame_Execute,
                            а не в GenerateConstellationsAndStars).
  - Секторы 8..18 (11 шт) — случайно размещённые (нейтральные)
  - Сектор 19     (1 шт)  — сюжетный сектор. Его центр копируется из ближайшего
                            расового сектора со сдвигом ±6/±4. В него попадают
                            звёзды 70 и 71 (сюжетные, fon_image = 0x47 = 'G').

  Имена всех 20 секторов хранятся в конфиге как "Constellations.Name.1" ...
  "Constellations.Name.20" и загружаются функцией Galaxy_SectorToString.

--- 3.2. Формирование полигональной карты ---

Вычисляется «средний размер сектора»:

    area_per_sector = MapWidth * MapWidth / num_sectors
    cell_size = round(sqrt(area_per_sector) * 0.75)

Вычисляются пороговые значения площади для валидации:
    min_area = 0.52 * MapHeight * MapWidth / num_sectors
    max_area = 1.5 * MapHeight * MapWidth / num_sectors

Создаётся прямоугольный полигон (Polygon2D), покрывающий всю карту [0..MapWidth,
0..MapHeight]. Вызов Polygon_SetFromRect задаёт этот прямоугольник.

Затем вызывается Polygon_SubdivideRecursive, который рекурсивно делит прямоугольник
на более мелкие полигоны. Это ключевой шаг — он строит базовое «полигональное
поле», к которому потом привязываются центры секторов.

Также к основному полигону добавляются дополнительные вершины по краям карты
с шагом 5.0 пикселей (flt_8515BC), формируя «рамку» из точек:
  - Вдоль верхнего и нижнего края (y=0 и y=MapHeight, x от 5 до MapWidth)
  - Вдоль левого и правого края (x=0 и x=MapWidth, y от 5 до MapHeight)

--- 3.3. Расстановка начальных «расовых» центров (8 секторов) ---

Игра имеет 8 рас (индексы 0..7). Для расстановки:

  1) Создаётся массив index[8] = {0,1,2,3,4,5,6,7}
  2) Случайным образом (0..3 раза, через RandRange(0,3)) массив перемешивается:
     для каждого элемента дважды вызывается Galaxy_ShuffleIndex (0x8731A0),
     которая реализует "сдвиг" значения по модулю [0..7] с рандомом
  3) Из 8 рас выбираются 4-5 «игровых» (index < 5), остальные — «крайние»
  4) Из игровых рас ещё случайно переставляются пары (4 обмена)
  5) Гарантируется, что раса игрока (dl) находится на определённой позиции

Расположение центров 8 первых секторов жёстко привязано к географии карты.
Каждый из 8 секторов получает координаты центра (поля +0Ch, +10h структуры
TConstellation) на основе следующей схемы:

  Сектор index[0]: (~cell_size*0.6+rand2, ~cell_size*0.6+rand2)
                    — верхний левый угол
  Сектор index[1]: (~MapWidth/2-1+rand2, ~cell_size*0.6+rand2)
                    — верхний центр
  Сектор index[2]: (~MapWidth-cell_size*0.6-2+rand2, ~cell_size*0.6+rand2)
                    — верхний правый угол
  Сектор index[3]: (~MapWidth-cell_size*0.4-2+rand2, ~MapHeight/2-1+rand2)
                    — правый центр
  Сектор index[4]: (~MapWidth-cell_size*0.6-2+rand2, ~MapHeight-cell_size*0.6-2+rand2)
                    — нижний правый
  Сектор index[5]: (~MapWidth/2-1+rand2, ~MapHeight-cell_size*0.6-2+rand2)
                    — нижний центр
  Сектор index[6]: (~cell_size*0.6+rand2, ~MapHeight-cell_size*0.6-2+rand2)
                    — нижний левый
  Сектор index[7]: (~cell_size*0.6+rand2, ~MapHeight/2-1+rand2)
                    — левый центр

Где rand2 = Galaxy_RandInt(0, 2) — небольшой случайный сдвиг.

Таким образом, 8 рас равномерно распределяются по периметру карты.

Дополнительно определяется сюжетный сектор: «последний» сектор
(Galaxy.constellations.count - 1 = 19) получает координаты, сдвинутые на ±6/±4
от ближайшего расового сектора. Направление сдвига зависит от того, в какой
половине карты расположен этот расовый сектор:
  - Если center_x < 0.15 * MapWidth → сдвиг вправо (+6), иначе влево (-6)
  - Если center_y < 0.20 * MapHeight → сдвиг вниз (+4), иначе вверх (-4)
При этом расовый сектор-источник тоже сдвигается в противоположную сторону на ±4.
Это создаёт пару «расовый + сюжетный» рядом друг с другом.

--- 3.4. Расстановка остальных центров секторов ---

Цикл: for var_C = 8 to (constellations.count - 2) = 18:
  (count=20, count-2=18, count-2-8=10, +1=11 итераций → секторы 8..18)
  Сектор 19 (последний) обрабатывается особо (см. выше, шаг 3.3).

Координаты генерируются случайно в пределах карты, с ограничениями:
  - Не ближе cell_size*0.4 пикселей от каждого края карты
  - Не должны попадать в тот же полигон (подъячейку Polygon2D), что и уже
    существующий центр
  - Минимальное расстояние до любого другого центра >= cell_size
  - Расстояние >= 7.0 (flt_8515F8)
  - До 100 попыток на каждый сектор

Проверка уникальности полигона реализована через Polygon_FindContaining — функция
ищет, в какую подъячейку полигонального дерева попадает точка. Если два центра
попали в одну и ту же ячейку — точка перегенерируется.

--- 3.5. Проверки валидности после расстановки ---

После размещения всех центров выполняются проверки:

  a) Площадь каждого Voronoi-полигона сектора (polygon +80h) должна быть в
     пределах [min_area, max_area]

  b) Вызов Polygon_IsDegenerate (0x838948) — проверка «вытянутости» полигона
     (если слишком вытянут — отбраковка)

  c) Подсчёт рёбер границы: суммируется Constellation.Lines.Count во все секторы
     (v118) и отдельно считаются «вырожденные» рёбра (v117) — отрезки, у которых
     x1==x2 или y1==y2 (горизонтальные/вертикальные сегменты на краю карты).
     Если 7*v117 > v118 (т.е. вырожденных более 1/7 от общих) — перегенерация.

  d) Проверка пересечения полигонов: Polygon_CheckOverlap (0x8389B4) проверяет,
     не пересекаются ли два полигона. Если да — перегенерация.

Весь процесс может повторяться до 1000 раз (var_B0 <= 0x3E8).
```

## 4. НАЗНАЧЕНИЕ ЗВЁЗД СЕКТОРАМ (TGalaxy_AssignStarsToConstellations)

```text
Адрес: 0x84FBD8 (вызывается из GenerateConstellationsAndStars+0xCE2, т.е. с 0x850C56)

Эта функция принимает TGalaxy и полигональное дерево (var_84).

Алгоритм:
  1) Инициализация полигональной структуры из переданного полигонального дерева.

  2) Для каждого TConstellation определяется полигон Voronoi:
     - Центр сектора (+0Ch, +10h) подаётся в Polygon_IsPointInside (0x8380BC)
     - Результат сохраняется в полигон сектора (+80h)
     Это Voronoi-ячейка — область карты, ближайшая к данному центру.

  3) Вычисляется число «звёздных точек», которые может содержать сектор:
     total_stars_per_sector = (num_sectors^0.5 / MapHeight / 3) * 0.5 + 1
     Первые 8 секторов получают +20 дополнительных очков, остальные — базовое
     значение.

  4) Итеративное назначение: для каждого сектора, пока есть «очки»,
     проходятся все звёздные позиции из списка сектора (+20h — PBound).
     Для каждой позиции:
       - Вычисляется новая позиция: (x + 3*dx + rand, y + 3*dy + rand)
       - Проверяется, попадает ли в пределы карты (> 0 и < MapWidth/MapHeight)
       - Через Polygon_IsPointInside определяется, в какой сектор попадает
       - Если попала — помечается флагом

  5) После итераций обновляются полигоны территории сектора (поле
     TConstellation.TerrainPoints @ +28h).

  6) Определяются соседи: для каждой пары секторов проверяется общая граница и
     при совпадении они записываются в TConstellation.Constellations (+1Ch).
```

## 5. ПОСТРОЕНИЕ СПИСКОВ РАССТОЯНИЙ (TGalaxy_BuildStarDistLists)

```text
Адрес: 0x84F418

Эта функция строит список отрезков, разделяющих Voronoi-ячейки соседних секторов.
Она работает с полигональными данными из Delaunay-триангуляции.

Алгоритм:
  1) Если список границ Galaxy.+168h уже существует — очищает его (Free items +
     Free list); иначе создаёт новый TList.

  2) Для каждого сектора (constellations) перебирает все рёбра его Voronoi-полигона
     (+20h — PBound). Каждое ребро проверяется: принадлежит ли оно ТОЛЬКО одному
     сектору (через TConstellation_PBoundContainsEdge, 0x856630 — для каждого
     другого сектора проверяет, содержит ли он то же ребро в своём PBound).

  3) Рёбра-границы (принадлежащие одному сектору, но не принадлежащие ни одному
     другому) собираются в отдельный список.

  4) Собранные рёбра сортируются вызовом TConstellation_ChainPBoundEdges
     (0x856A2C, ранее sub_856A2C): если два ребра имеют общую вершину
     (Polygon_PointsEqual, 0x837094), они располагаются последовательно, формируя
     непрерывную цепочку. Если ребро «перевёрнуто» — его концы меняются местами.

  5) Финальный проход: для каждого отрезка проверяется, лежит ли его начальная
     точка как вершина в PBound более чем одного сектора
     (TConstellation_PBoundContainsVertex, 0x856918). Если в 2+ — это узловая
     точка стыка секторов; отрезок добавляется в Galaxy.+168h как элемент
     TStarDist (8 байт: 2 float — координаты x,y точки).
```

## 6. ПРОВЕДЕНИЕ ГРАНИЦ СЕКТОРОВ (TGalaxy_BuildSectorBoundary)

```text
Адрес: 0x84F938

Вызывается для каждого сектора отдельно: TGalaxy_BuildSectorBoundary(Galaxy, index)

Алгоритм:
  1) Получить TConstellation по индексу из Galaxy.Constellations

  2) Перебрать все рёбра PBound (+20h) сектора. Для каждого ребра проверить:
     находится ли оно на «краю карты». Граничные точки копируются в отдельный
     список.

  3) Проверка «точка на краю карты»:
     - Если Galaxy.+168h пуст: проверяет, совпадает ли координата x или y
       точки с 0 или MapWidth/MapHeight
     - Если Galaxy.+168h существует: проверяет, лежит ли точка на одном из
       отрезков-границ (через Polygon_PointsEqual, 0x837094)
     - Также проверяет, в скольких Voronoi-ячейках лежит точка
       (TConstellation_PBoundContainsVertex, 0x856918). Если в 3+ — это
       узловая точка (стык трёх и более секторов).

  4) Очищаются скрытые границы (PBoundHidden, +24h).

  5) Из найденных граничных точек формируются отрезки: каждая пара соседних
     точек → отрезок (x1,y1, x2,y2) размером 28 байт. Отрезки добавляются
     в PBound (+20h).

  6) Вызывается TConstellation_RecalcRectFromPBound (0x856470) — пересчёт
     Rect/Size сектора по только что построенному PBound.

  7) Формируется полигональное представление границы:
     - Для каждого отрезка из списка граничных точек создаётся Polygon2D
       через TPolygon2D.Create (0x837424), с передачей центра сектора (+0Ch)
       и концов отрезка
     - Полигоны объединяются через Polygon_SubdivideRecursive (0x837A8C)

  8) Результат сохраняется в TConstellation.TerrainPoints (+28h) — это и есть
     визуальная граница сектора на карте.
```

## 7. РАЗМЕЩЕНИЕ ЗВЁЗД НА КАРТЕ

```text
После создания секторов и построения границ, в основной функции
TGalaxy_GenerateConstellationsAndStars идёт цикл размещения звёзд
(~адрес 0x850F56 и далее, тело — 0x850F7A..0x85135D).

В начале каждой итерации регенерации (до 50 раз) для каждого сектора
вызывается TConstellation_ClearStarsList (0x855BE8), которая через TList.Clear
(VMT[2]) очищает список Stars. Затем все TStar.Pos обнуляются.

Для каждой звезды из списка Galaxy.stars (поле +2Ch):
  1) Определяется целевой сектор (var_64) по номеру звезды (var_C = 0..72):

     if star_index == 70 or star_index == 71:
         sector = constellations.count - 1    // = 19, сюжетный сектор
     elif star_index < 65:
         sector = star_index % 18             // равномерно по первым 18 секторам (0..17)
     elif star_index <= 68:
         sector = 18                          // жёстко в 18-й сектор
     elif star_index > 68:
         sector = star_index % (count - 1)    // = star_index % 19

     Таким образом, первые 65 звёзд распределяются циклически по 18 секторам
     (по ~3.6 звезды на сектор), звёзды 65-68 идут в 18-й, 70-71 в сюжетный (19-й),
     а 69 и 72 — по модулю 19.

  2) Далее для первых ~69% звёзд (star_index < num_stars / 1.46 ≈ 50)
     с вероятностью 60% (RandExt < 0.6) — вместо назначенного сектора выбирается
     сектор с максимальным соотношением (площадь / количество_уже_назначенных_звёзд),
     то есть наиболее «пустой». Это балансирует плотность звёзд по секторам.

     При этом первые 8 секторов (расовые) пропускаются в этом выборе, если
     star_index >= 65 (0x41) и sector_index < 8.

  3) Вызывается TConstellation_InitStars (0x855AC0), привязывающая звезду
     к сектору.

  4) Вычисляются координаты:
     - Перед циклом TConstellation_RecalcRect (0x855C28) возвращает площадь
       Voronoi-полигона (имя в IDB вводит в заблуждение: это wrapper над
       Polygon_CalcArea, не пересчёт Rect)
     - Берутся уже посчитанные Rect (+2Ch..+38h) и Size (+3Ch..+40h)
     - Генерируется случайная точка внутри rect через Galaxy_RandInt по Size
     - Добавляется смещение 0.0 (фактически нулевое)

  5) Проверки координат звезды:
     - x + 0.5 >= 8.0  И  x + 0.5 <= MapWidth - 8
     - y + 0.5 >= 5.0  И  y + 0.5 <= MapHeight - 8
     → не ближе ~8 пикселей от краёв

  6) TConstellation_PointInSector (0x856594) — проверка, что точка внутри
     полигона сектора (обёртка над Polygon_IsPointInside для поля +80h).

  7) TConstellation_PointNearBoundary (0x856990) — проверка, что точка не
     ближе 2.0 к любому ребру границы сектора (PBound). Если близко — отклонить.

  8) Проверка расстояния до всех предыдущих звёзд: dist >= 4 (жёсткий минимум)

  9) Дополнительная проверка: если расстояние > var_3C (расчётный порог
     «разреженности» через Galaxy_CalcStarDistThreshold, 0x73A610) И мы в
     стартовом секторе И это одна из первых GalaxyFlags(=20) звёзд — отклоняем
     (чтобы игрок не оказался в пустом секторе).

  10) Если расстояние < var_60 (минимальный «средний шаг» = sqrt(stars/sectors)*0.5)
      И попыток < 20 — отклоняем (ещё можно найти лучше)

  11) Максимум 100 попыток на каждую звезду
```

## 8. ФИНАЛЬНАЯ ВАЛИДАЦИЯ И ПЕРЕГЕНЕРАЦИЯ

```text
После размещения всех звёзд:
  1) Проверяется, нет ли двух звёзд, у которых |x1-x2| < 7 И |y1-y2| < 2
     (слишком близко). Если есть — var_35 = 1, перегенерация.

  2) Проверяется связность: строится динамический массив visited[num_stars],
     начиная от стартовой звезды (раса игрока) распространяется «волна» —
     если расстояние между двумя звёздами <= var_3C (порог), они считаются
     связанными. Должны быть связаны минимум 3 звезды, иначе перегенерация.

  3) Вызывается Galaxy_ValidateAllConstellations (0x84FB7C) — дополнительная
     проверка, что все секторы имеют корректную геометрию.

Весь процесс (шаги 4-8) может повторяться до 50 раз (var_B0 <= 0x32).
```

## 10. КОНСТАНТЫ И «МАГИЧЕСКИЕ ЧИСЛА»

## ИТОГ

```text
Генерация галактической карты в Space Rangers 2 использует комбинацию:
  1) Voronoi-разбиения для формирования секторов
  2) Рекурсивного деления полигонов (BSP-подобного) для пространственного
     индексирования
  3) Жёсткой привязки 8 рас к позициям по периметру карты
  4) Случайного размещения остальных секторов с контролем расстояний и площадей
  5) Многократной итеративной перегенерации при нарушении ограничений

Ruins (космические станции, TRuins — наследник TShip) не участвуют в процессе
деления на секторы. Они размещаются позже, в MB_Galaxy_setup, после того как
карта с секторами и звёздами уже полностью сгенерирована.

Стартовый сектор игрока — один из первых 8 расовых, определяется уже после
генерации карты: в TThreadCreateNewGame_Execute перебираются все звёзды и их
планеты, ищется планета с owner == player_race. 20-й (index 19) сектор — сюжетный,
а не стартовый.
```
