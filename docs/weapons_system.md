# Система оружия (WeaponSystem) — описание и оценка

## 1. Обзор

Система оружия — это пошаговая модель тактического боя в звёздной системе. Каждый «ход» (день) разбит на 10 **сабтёрнов** (`GalaxyData.SubTurnsPerTurn`), внутри которых корабли стреляют, ракеты движутся, эффекты тикают. Расчёты живут отдельно от рендера: `WeaponSystem` чистый статический класс, а `WeaponVisualSystem` подхватывает события из `TurnAnimationData` уже после симуляции.

**Ключевые файлы:**
- `Assets/Scripts/Systems/WeaponSystem.cs` — расчёт выстрела, урона и эффектов.
- `Assets/Scripts/Systems/MissileSystem.cs` — управление активными ракетами между ходами.
- `Assets/Scripts/Ships/CombatData.cs` — все боевые модели данных (DamageType, HitPattern, эффекты, щит, ракеты).
- `Assets/Scripts/Visual/WeaponVisualSystem.cs` — рендер VFX выстрелов и попаданий.
- `Assets/Scripts/Generation/GalaxyDataModels.cs` (`CombatSubTurn`, `ProcessPlayerManualShot`) — точка входа для симуляции боя.
- `Assets/Scripts/Equipment/EquipmentSystem.cs` — хранение оружия в слотах, износ, состояние щита.

## 2. Модель данных

### Типы урона (`DamageType`)
- **Kinetic** — хорошо против брони, слабо против щита.
- **Explosive** — средне против брони, сильно против незащищённых.
- **Energy** — перегружает щит (множитель `EnergyShieldOverloadMult = 1.5`), хуже против корпуса.

### Паттерны выстрела (`HitPattern`)
- **Point** — точечный одиночный.
- **Piercing** — пробивает насквозь.
- **Shotgun** — конус снарядов.
- **Ricochet** — рикошет до 5 раз.
- **Chain** — переход с цели на цель.
- **AoE / PointAoE** — площадь / точка + взрыв.
- **Falloff** — урон падает с дистанцией.
- **Beam** — луч.
- **Homing** — самонаводящаяся ракета (особый путь через `MissileSystem`).
- **Mine** — стационарная мина.

> Заметим: на уровне расчёта урона `HitPattern` пока влияет только на визуал и развилку «ракета или мгновенный выстрел». Логика самих паттернов (рикошет, цепной разряд, конус) ещё не реализована — это слот под будущее расширение.

### Эффекты (`CombatEffectType`)
Боевые: Slow, Shutdown, ArmorDebuff, Jamming, EngineDisable, Drain.
Тактические (требуют превосходство сканера): BlockWeapon, BlockDroid, ExecuteBonus.
Экономические: LootFocus.

Эффекты хранятся в `ShipData.ActiveEffects` как `ActiveCombatEffect(Type, TurnsLeft, Magnitude, SourceUid)`. Тикаются в `WeaponSystem.TickEffects` раз в ход. Некоторые суммируются с капом (Slow ≤ 0.75, ArmorDebuff ≤ 200), некоторые обновляют длительность по `SourceUid`, Shutdown перезаписывается.

### Щит (`ShieldState`)
Не «вторая полоска HP», а **процентный барьер с ёмкостью и регенерацией**:
- `MaxCapacity / CurrentCapacity` — ёмкость, восстанавливается на `RegenRate` за ход.
- `BlockPercent` — доля поглощаемого урона.
- `Absorb(damage, penetration, energyMult)`:
  - `penetrated = damage * penetration` (проходит мимо).
  - `blocked = damage * (1 - penetration)` → проходит `blocked * (1 - block%)`.
  - Ёмкость уменьшается на разницу × `energyMult`.

### Параметры выстрела (`WeaponShotParams`)
Структура, собранная из конфига оружия в `BuildShotParams`:
MinDmg/MaxDmg, Range, ArmorPenetration, ShieldPenetration, EquipHitChance, EquipDamage, Ammo, DamageType, HitPattern, и список Effects.

### Активная ракета (`ActiveMissile`)
Персистируется в `StarData.ActiveMissiles`. Имеет HP, Speed, DaysLeft, графику и **снимок параметров выстрела** на момент запуска (включая бафы атакующего). Если ракета летит несколько дней, она сохраняется между ходами.

## 3. Цикл боя

В `GalaxyDataModels.CombatSubTurn` каждый сабтёрн:

1. **Игрок** — ручной выстрел из `ProcessPlayerManualShot` (только в сабтёрне 1).
2. **NPC** — каждый живой не-выключенный (`Shutdown`) корабль ищет ближайшую враждебную цель через `OwnerRaceRelationsManager.AreHostile`.
3. Для каждого слота оружия:
   - Вычисляется `ShotDuration` (количество сабтёрнов на перезарядку).
   - Если `subTurn == nextFiringSubTurn` и оружие работает и цель в радиусе — стрельба.
   - Для `HitPattern.Homing` → `MissileSystem.LaunchMissile`. Иначе → `WeaponSystem.ProcessShot`.
4. **MissileSystem.TickMissiles** — движение всех ракет на `missile.Speed`; при попадании (расстояние < `HitRadius = 0.2`) → `ApplyMissileImpact`.

В конце дня — `MissileSystem.TickMissilesEndOfDay` уменьшает `DaysLeft`, истёкшие ракеты взрываются.

## 4. Формула урона (`CalculateDamage`)

Последовательность применения:

```
1. baseDamage = Random(MinDmg, MaxDmg)
2. ExecuteBonus: до +33% при ExecuteBonus-эффекте у атакующего/цели и низком HP цели
3. Уязвимость:  afterVuln = baseDamage * HullSusceptibility[DamageType]
4. Броня:       absorption = clamp(armor - ArmorPenetration, 0, afterVuln * 0.75)
                afterArmor  = afterVuln - absorption
                (армор-кап 75% — броня не может поглотить больше)
5. Щит:         если ShieldState активен — Absorb(afterArmor, ShieldPen, energyMult)
                energyMult = 1.5 для DamageType.Energy
6. Результат:   (hullDamage, shieldCapacityLost)
```

> Важно: в коде есть комментарий, что дизайн-документ требует порядка «уязвимость → щит → броня», но реализован «уязвимость → броня → щит» (броня работает всегда, щит ловит остатки). Это явное осознанное отклонение, задокументированное в исходнике.

## 5. Дополнительные механики выстрела

**Попадание по оборудованию.** При шансе `EquipHitChance` выбирается случайный слот цели, у которого `CanBeDamagedByWeapon = true`, и снимается `EquipDamage` дюрабилити. Это даёт глубину боя — выстрел может выбить именно двигатель/радар, а не просто снять HP.

**Износ.** После каждого выстрела:
- `ApplyWeaponShotWear(attacker)` — износ самого оружия.
- `ApplyShieldHitWear(target)` — износ щита при поглощении урона.

**Боеприпасы.** Если `Ammo >= 0`, после выстрела уменьшается на 1; при `< 0.5` оружие не стреляет.

**Артефакты.** `AppendArtifactEffects` пробегает по слотам `Artefacts` и добавляет эффекты из их `ShotEffects` к каждому выстрелу. Это компонентный способ накладывать пассивные модификаторы.

**Сканер-доминанта.** Эффекты `BlockWeapon` и `BlockDroid` применяются только если у атакующего сканер мощнее, чем у цели (`CheckScannerDominance`). Это превращает Scanner в тактически важный модуль.

**Drain (вампиризм).** Часть нанесённого урона корпусу возвращается атакующему как HP, ограничено `MaxHull`.

## 6. Ракеты (MissileSystem)

Самостоятельная подсистема для `HitPattern.Homing`:

1. **LaunchMissile** создаёт `ActiveMissile` со снимком параметров выстрела и добавляет в `star.ActiveMissiles`. Регистрирует визуал запуска (`ShotEvent` с `DamageDealt=0`).
2. **TickMissiles** в каждом сабтёрне двигает все ракеты на `Speed` к цели:
   - Если цель убита/исчезла → ракета удаляется.
   - Если расстояние < `HitRadius` → `ApplyMissileImpact` (применяет тот же `CalculateDamage`).
   - Иначе обновляет `MissileFrames` для анимации.
3. **TickMissilesEndOfDay** уменьшает `DaysLeft`, истёкшие ракеты «взрываются в космосе» (лог в консоль).
4. **InitMissileFrames** в начале каждого дня заново регистрирует визуал летящих ракет.

Ключевая особенность: ракета — это **полноценная сущность с HP** и со своим `DamageType`. Снимок параметров на старте делает её устойчивой к смерти атакующего и изменениям его снаряжения.

## 7. Визуализация (`WeaponVisualSystem`)

Подписывается на события `ShotEvent` в `TurnAnimationData.Shots`, генерируемые `ProcessShot`/`LaunchMissile`/`ApplyMissileImpact`. Использует пул `SpriteRenderer`/`LineRenderer` и каскад цветов:

- **Main** — цвет тела снаряда (палитра оружия → дефолт по `DamageType`).
- **Core** — белая сердцевина луча.
- **Trail** — след.
- **Impact** — искры на попадании (`HitEffect.ColorSpark` → палитра → дефолт по `DamageType`).

Sprite-режим: если у оружия `Visual.IsSprite == true`, грузит спрайт из `Resources` (с кэшем). Hit-эффекты — формы: Sparks, Ring, Burst, Flash.

## 8. Интеграция с оборудованием

`EquipmentSystem` хранит экземпляры предметов в `ship.Equipment.Slots` (slotKey → itemUid) и `ship.AllItems` (uid → ItemInstance). Изменения снаряжения вызывают:

- `RebuildShieldState` — пересоздание `ShieldState` при смене щита.
- `InvalidateWeaponSlotsCache` — сброс кэша отсортированных слотов оружия (используется в `CombatSubTurn` для очерёдности стрельбы).

`GetSortedWeaponSlots()` гарантирует детерминированный порядок выстрелов: важно для воспроизводимости боя при том же сиде.

## 9. Оценка системы

### Сильные стороны

1. **Сильное разделение симуляции и визуала.** `WeaponSystem` — чистый статический класс, не лезет в Unity. `WeaponVisualSystem` подхватывает события через `ShotEvent` — это даёт возможность гонять бой headless, проигрывать одну и ту же битву ускоренно или с разными VFX.
2. **Богатая модель данных.** 3 типа урона × 11 паттернов × 10 эффектов × щит × броня × сканеры — простор для интересных билдов снаряжения. Артефакты как источник дополнительных эффектов — приятная компонентная архитектура.
3. **Щит как процентный барьер.** Это даёт интересные геймплейные решения (BlockPercent ≠ HP), а энергетический бонус (×1.5 расхода ёмкости) даёт смысл выбору `DamageType`.
4. **Стрельба по оборудованию.** Серьёзная глубина боя — можно отстреливать двигатели, радары, выбивать оружие. Контролируется одним шансом, не раздувает код.
5. **Ракеты как персистентные сущности.** Снимок параметров на запуске + жизнь в днях делает их интересным стратегическим элементом, а не просто отложенным уроном.
6. **Тактические эффекты, требующие сканера.** Связывает Scanner с боевой эффективностью — модуль становится осмысленным выбором, а не «галочкой».
7. **Износ снаряжения.** Стрельба изнашивает оружие; поглощение урона изнашивает щит. Это естественный сток ресурсов в долгую кампанию.
8. **Артефактные эффекты через данные.** Артефакт — это просто `ItemInstance` с параметром `ShotEffects`, добавляющий эффекты к каждому выстрелу. Расширение поведения без правки кода.

### Слабые стороны и риски

1. **Многие HitPattern не реализованы.** `Piercing`, `Shotgun`, `Ricochet`, `Chain`, `AoE`, `PointAoE`, `Falloff`, `Beam`, `Mine` — все отрабатывают как `Point` на уровне расчёта. Это серьёзный недостроенный слой: либо реализовать, либо убрать из enum и Honest комментариях.
2. **Игнор цели за пределами радиуса.** В `CombatSubTurn` цель ищется как **ближайшая** враждебная вообще, без учёта дальности оружия. Если она вне `range`, корабль молчит, но не выбирает другую цель. Стоит фильтровать кандидатов по `weapon.Range`.
3. **Парсинг эффектов из строки.** `ParseEffects("Slow:2:0.3:0.5")` через `Split(':')` — хрупко: легко ошибиться в формате, ошибка молчаливо превращается в дефолтные значения. Желательно валидировать на этапе загрузки конфига и кешировать готовый `List<WeaponEffect>` в `ItemInstance`.
4. **`BuildShotParams` вызывается на каждый выстрел.** Парсинг строк (`DamageType`, `HitPattern`, `Effects`), вызовы `GetParam` — всё это можно подсчитать один раз при экипировке. На 30 кораблей × 5 оружий × 10 сабтёрнов × 365 ходов — пара миллионов лишних парсингов в год.
5. **Жёсткие константы.** `ArmorAbsorptionCap = 0.75`, `EnergyShieldOverloadMult = 1.5`, `ExecuteBonus = +33%` — всё в коде. Балансёр должен ходить в исходники, чтобы покрутить параметры.
6. **Снимок параметров ракеты.** Это плюс по дизайну, но не учитывает прокачку/смену артефактов атакующего во время полёта. Если игрок специально потратил ход на улучшение, не нравится, что ранее запущенные ракеты не воспользуются.
7. **`ApplyMissileImpact` дублирует логику `ProcessShot`.** Те же шаги: ExecuteBonus → CalculateDamage → износ → EquipHit → эффекты. Логика буквально скопирована. Лучше вынести в общую `ApplyHit(shot, attacker, target)`.
8. **Урон по астероидам и кораблям расходится.** `AsteroidSystem.PlayerShootAsteroid` идёт отдельным путём в `AsteroidSystem`, минуя `WeaponSystem`. Это нарушает единое поведение оружия (например, эффекты не сработают).
9. **`Drain` восстанавливает HP `attacker`,** но если атакующий — ракета (запущена давно), `attacker` для `ApplyMissileImpact` ищется заново — он может быть мёртв или отсутствовать. В коде есть `attacker == null` защита в начале `ApplyExecuteBonus`, но в `Drain` `attacker` используется без проверки.
10. **`HasEffect`/`GetTotalEffectMagnitude` линейные.** Для горячего пути (вызывается каждый сабтёрн на каждый корабль) можно держать словарь по типу эффекта в `ShipData`.
11. **Состояние `Ammo` хранится в `Params["Ammo"]` как float.** Сравнения `< 0.5f` и приведения `RoundToInt` шумно — лучше отдельное поле `int CurrentAmmo`.
12. **`anim?.DeathUids.Add(target.Uid)`** — дубликат-чек делается через `Contains`, что O(N). При большом числе смертей за бой стоит использовать HashSet.
13. **`Range / 100f` повторяется** при каждом выстреле — `Range` хранится в «процентах от системы», но единицы пересчёта приколочены константой. Можно сразу хранить нормализованное значение.
14. **Игрок и NPC дублируют структуру выстрела.** `CombatSubTurn` и `ProcessPlayerManualShot` имеют почти одинаковый цикл (поиск цели → перебор оружия → запуск). Можно объединить в `FireAllWeapons(attacker, target)`.

### Качество кода

- **Хорошее** — структуры данных задокументированы, имена осмысленные.
- **Комментарии** уровня «зачем», а не «что».
- **Дизайн-документ** упоминается в коде с указанием на сознательное отклонение — это очень здраво.
- **Тестов нет** — критично для системы с такой формулой урона: легко словить регрессию при ребалансе.

### Сводная оценка

| Критерий              | Оценка | Комментарий                                                            |
|-----------------------|:------:|------------------------------------------------------------------------|
| Архитектура           |   8/10 | Чистый расчёт отделён от визуала                                       |
| Глубина боёвки        |   8/10 | Тип урона × щит × броня × эффекты × сканеры × оборудование             |
| Полнота реализации    |   5/10 | Большая часть HitPattern не реализована                                |
| Производительность    |   6/10 | Парсинг строк каждый выстрел; линейный поиск эффектов                  |
| Конфигурируемость     |   5/10 | Магические числа в коде                                                |
| Сопровождаемость      |   7/10 | Дублирование Process/ApplyMissile; разные пути для астероидов          |
| Тестируемость         |   8/10 | Статические чистые методы, но тестов нет                               |
| Визуал                |   8/10 | Палитра + HitEffect + спрайтовый режим — гибко                         |

**Итог: 7/10.** Серьёзный фундамент с продуманной моделью данных и хорошим разделением слоёв. Главные задачи на доработку — реализация всех `HitPattern`, вынос баланса в конфиг, кэширование `WeaponShotParams` и объединение дубля `ProcessShot`/`ApplyMissileImpact`. После этого систему можно считать продакшен-готовой.
