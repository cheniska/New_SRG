0. КРАТКОЕ РЕЗЮМЕ
================================================================================
Расчёт траектории корабля в SR2 разнесён на три уровня. Один игровой ход
для одного корабля проходит по цепочке:

  (1) ЗАДАНИЕ ПРИКАЗА — UI или AI пишет в поля корабля:
        ship.Order      @ +0x428  uint8  (тип приказа: NONE/MOVE/.../JUMP/FOLLOW)
        ship.OrderData  @ +0x42C  uint32 (доп. параметры)
        ship.DestObj    @ +0x430  TObject* (цель: TShip/TPlanet/THole/...)
        ship.DestPos    @ +0x434  _pair_float (X,Y) — конкретная точка
      Для игрока дополнительно:
        Player.dest_star @ +0x5CC TStar* — звезда межзвёздной цели

  (2) РАСЧЁТ МАРШРУТА НА ОДИН ДЕНЬ —
        TShip_CalcRoute     @ 0x7219B0
      Switch по ship.Order, для каждой ветки решает целевую точку (с учётом
      радиуса посадки на планету, точки прыжка через дыру, точки догоняющего
      движения и т.д.), затем вызывает sub_722A10/sub_723A6C — реальный
      A*-планировщик с обходом препятствий.

  (3) АНИМАЦИЯ ПО КАДРАМ МЕЖДУ ХОДАМИ —
        TShip_StepDay_MoveProcessor @ 0x720090 → TShip_MoveAlongRoute @ 0x71FE10
      Корабль хранит "плёнку" waypoints в ship[+0x440]. Каждый кадр
      MoveAlongRoute берёт следующий waypoint, переставляет ship.Pos и
      ship.Angle, вызывает TFilm_OrderMove чтобы переместить
      видимый графический объект.

  Для игрока шаги (1)→(2)→(3) такие же, но шаг (1) запускает **клик мышью
  на космической карте**:
        MB_TMainForm_OnSpaceClick @ 0x7AF0E8
      switch по типу цели (TShip / THole / TRuins / TPlanet / TItem /
      TAsteroid / TMissile) — выставляет Order и сразу вызывает CalcRoute,
      чтобы построить путь и показать его игроку до конца хода.

  Отрисовка "линии курса игрока" — это сама плёнка waypoints: видимая
  стрелка/трасс — это последовательность позиций ship.f440, отрендеренная
  через GFilm. Отдельной "DrawCoursePath" функции нет; плёнка строится
  ВНУТРИ CalcRoute->sub_723A6C, а отрисовывается TFilm-системой.

3. ПОВЕДЕНИЕ ПО Order — ВЕТКИ ВНУТРИ TShip_CalcRoute (0x7219B0)
================================================================================
Switch по ship.Order (+0x428):

  Order == 0         (NONE)
    — ничего не делает, ship не двигается.

  Order == 1, 3, 5   (MOVE / некий "force" / TAKE_OFF и т.п.)
    — LABEL_84: вызывается sub_722A10(ship, &ship.DestPos, day_step) —
      простое движение к точке DestPos через A*-планировщик.

  Order == 2         (FOLLOW_OBJ — лететь к TShip или TPlanet)
    Если DestObj — TShip:
      • Если расстояние ≤ ~5e38 (фактически всегда): обновить DestPos
        точкой DestObj.Pos и вызвать CalcRoute(ship, DestPos, day).
        Если плёнка пустая после первой попытки — рандомный сдвиг ±5
        (через Galaxy_RandInt) и повторить.
      • Если очень далеко — отдалить DestPos в направлении объекта.
    Если DestObj — TPlanet:
      v76 := planet.size + 150  (граница обнаружения)
      v75 := planet.size + 50   (зона посадки)
      Если это ИГРОК — особая логика: бинарный поиск точки на
        планетной орбите такой, чтобы расстояние от текущей Pos было
        минимальным (правильный заход на посадку).
      Иначе для NPC — простая случайная точка в радиусе orbital ring.

  Order == 4         (JUMP_HOLE — прыжок через дыру)
    DestObj — THole. По OrderData выбирается какой "конец" дыры
    использовать (THole имеет 2 позиции: Pos1 @ +12, Pos2 @ +24).
    Если расстояние слишком велико — слегка отойти от цели рандомно
    (±20°), иначе двигаться к дыре через CalcRoute.

  Order == 6         (FOLLOW_SHIP — следовать за чужой плёнкой)
    DestObj — TShip с собственной плёнкой ship2.RouteFilm @ +0x440.
    Если у DestObj есть следующий waypoint:
      • CalcRoute берёт его как цель;
      • после CalcRoute копирует в ship.DestPos позицию
        последнего своего waypoint'а (если есть) или текущую Pos,
        чтобы UI отобразил "пунктир к концу строки".
    Использует TShip_UpdateEngine для расчёта скорости.

  Order == 3         (отдельная ветка после switch — гипер-арка)
    Используется когда корабль уже летит на выход из системы:
    TStar_CreateArrivalAnimation создаёт анимацию исчезновения,
    sub_722A10 пишет в плёнку точку "в бесконечность" по углу к
    исходной звезде; если корабль уже за пределами PlayerStar -
    TShip_ProcessHyperspaceArc создаёт дугу гипера, TStar_ProcessCombatResults
    регистрирует выход. По окончании ставится ship[+0x444] = 1.

  Особая ветка для Terron_p (босс): если ship.Order == 1 и Galaxy.TerronToStar
  не выставлен — вызывается TStar_ProcessCombatRound_0 (Терон управляется
  отдельно).

================================================================================
4. A*-ПЛАНИРОВЩИК И ПЛЁНКА ПУТИ
================================================================================
  ship[+0x440] — указатель на структуру "RouteFilm":
        +0    head             — первый узел (uint*)
        +4    next             — следующий waypoint (от которого считаем)
        +8    last_node        — последний созданный waypoint
        +20   waypoint_count   — счётчик (для guard'а длины плёнки)
  Каждый waypoint:
        +0    next             — следующий
        +8    pos.x            — float
        +12   pos.y            — float
        +16   angle            — float (угол курса в этой точке)

  sub_722A10 @ 0x722A10  (TShip_PushDestination)
    Обёртка над sub_723A6C(ship, &target_xy, day_step). Дополнительно:
    если ship.CurStar == PlayerStar AND плёнка короче 200 кадров AND
    игрок не на планете (или Player.Order == 5 — взлёт) — расширяет
    плёнку до 200 точек через sub_4D813C (interpolate fill). Это
    гарантирует плавную анимацию ВСЕХ кораблей видимой игроку звезды.
    После записи последнего узла — если новая точка очень близко
    (< Speed*200*star_factor) — перезаписывает последний waypoint
    новой целью (smoothing).

  sub_723A6C @ 0x723A6C  (TShip_PlanPath)
    Настоящий планировщик. Использует:
      sub_871CD8  — двигает точку отступа (offset margin)
      sub_872390  — проверка пересечения сегмента с препятствием
      sub_872734  — построение касательных вокруг препятствия
                    (даёт ДВЕ обходные точки, выбирается ближняя)
      CalcDistanceSquared (0x8728AC) — Dist2 inline
    Радиус препятствия = ship.CurStar[+92] (avoidance radius звезды —
    обычно радиус самой большой планеты в системе плюс margin).
    Если total distance > 2*radius * 2*radius — добавляет waypoint
    через sub_722964 (прямое append), иначе считает обход.
    На большие дистанции (вне расчётного circle) вызывает
    TShip_ProcessHyperspaceArc — это уже подготовка дуги гипер-вылета.
    После добавления waypoint'а делает рекурсивный вызов через
    sub_723DF4 для следующего сегмента.

  ИТОГ:  ship.RouteFilm в любой момент содержит цепочку waypoint'ов,
         которые UI рисует через GFilm. Это и есть "линия курса" игрока
         (для NPC — то же самое, но игрок их не видит, пока не наведёт
         внимание).

5. АНИМАЦИЯ ПО КАДРАМ — TShip_MoveAlongRoute
================================================================================
  TShip_StepDay_MoveProcessor @ 0x720090 (3.6 KB) — главный процессор
    движения корабля для UI-режима "play turn". 9 вызовов
    TShip_MoveAlongRoute (для разных состояний корабля и фаз кадра).

  TShip_MoveAlongRoute @ 0x71FE10 — один шаг по плёнке:
    if (ship.RouteFilm.head && ship.RouteFilm.head.next) {
        ship.RouteFilm.next = ship.RouteFilm.head.next;
        if (ship.is_visible) {                   // HIBYTE@ +0x423
            uint8 new_angle256 = AngleGraTo256(ship.RouteFilm.next.angle);
            if (AngleGraTo256(ship.Angle) != new_angle256)
                sub_7CFA28(GFilm, ship.Id, ship.GraphShip, new_angle256);
        }
        ship.Pos.x  = ship.RouteFilm.next.pos.x;
        ship.Pos.y  = ship.RouteFilm.next.pos.y;
        ship.Angle  = ship.RouteFilm.next.angle;
        sub_4D7C9C(ship.RouteFilm.head, ship.RouteFilm.head.next); // удалить пройденный узел
    }
    if (ship.is_visible) {
        TFilm_OrderMove(ship.GraphShip,        ship.Id, &ship.Pos);
        if (ship.SecondaryGraph)               // +0x4AC
            TFilm_OrderMove(ship.SecondaryGraph, ship.Id, &ship.Pos);
        if (Player() == ship)
            sub_7CFF54(GFilm, ship.Id, &ship.Pos);  // ★ доп. логика для камеры
                                                    // (центрирование вида)
        // fade для гипер-прыжка:
        if (ship.AlphaDelta != 0) {              // +0x48C
            ship.Alpha += ship.AlphaDelta;       // +0x488
            sub_7CF9C0(GFilm, ship.Id, ship.GraphShip, clamp(ship.Alpha,0,255));
        }
    }

  → TFilm_OrderMove (0x7CF8F4) — это и есть "плёнщик". Он добавляет
    в очередь GFilm приказ "переместить графический объект GraphShip
    в позицию Pos на кадре step". GFilm затем интерполирует и рисует
    кадры между ходами, что игрок и видит как полёт корабля.
  → sub_7CFF54 для Player'а — вероятно "центрировать вид камеры на
    Player.Pos" (нужно проверить).

6. ОТРИСОВКА ТРАЕКТОРИИ ИГРОКА
================================================================================
  Главное наблюдение: ОТДЕЛЬНОЙ функции "Draw player course line" в
  индексе нет. Видимая на главной карте трасса = последовательность
  waypoints из ship.RouteFilm, отрендеренная как:
    1) кадр-за-кадром позиция самого корабля (GraphShip);
    2) GFilm рисует трассы движения для всех объектов на которые
       была команда OrderMove — игроку показывается пунктир/стрелка
       автоматически.

  Это объясняет, почему OnSpaceClick (0x7AF0E8) вызывает TShip_CalcRoute
  8 раз сразу же — после клика плёнка перестраивается и игрок ВИДИТ
  новый путь до конца хода без ожидания "End Turn". То есть UI не
  "рисует курс" руками — он строит плёнку, а её рисует GFilm.

  То что в TfAB_* (форма аркадной мини-игры в пещере доминатора)
  есть Draw*Path* функции — это другая система: пещерная мини-игра
  имеет собственный рендер пути, не использующий GFilm:
        TfAB_AddPathNode       @ 0x69BF98
        TfAB_UpdateShipPath    @ 0x69C268
        TfAB_RenderShipPath    @ 0x69C56C
        TfAB_DrawShipPathEnd   @ 0x69C6B4
        AB_Zone_DrawPath       @ 0x68CC60
  К звёздной/галактической траектории отношения не имеют.

  Глобалы UI (подтверждены через декомпиляцию):
        Player()           @ 0x78C078 — указатель текущего игрока
        AutoBattleShip     @ 0x8824AC — подменяет Player в авто-бою
        gvar_00882B38[0]                — PlayerStar (текущая звезда игрока)
        Galaxy             @ 0x88263C
        GFilm              — доступ через gvar_00882D74 (видно из MoveAlongRoute)
