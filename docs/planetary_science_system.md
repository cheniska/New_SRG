# Научное развитие планет — диздок

Скрытая система галактических исследований, которая **наполняет смыслом** существующие
метрики ПТУ (планетарный тех-уровень, 1–10) и ГТУ (галактический, 1–10). Цель — заменить
текущий «прогресс ПТУ растёт по таймеру» на **изобретения**, которые двигают ПТУ
вверх и параллельно меняют игровой мир (новые типы оборудования, новости, события,
модификаторы).

Документ — план архитектуры и поведения. Реализация — отдельный спринт.

---

## 1. Цели

- **Сохранить** существующий API: `PlanetData.TechLevel` (ПТУ 1–10), `GalaxyData.GtuLevel`
  (ГТУ 1–10), `PlanetaryTechSystem.TickAll`. Внешние потребители (`ItemFactory`,
  `EquipmentShopSystem`, диалоги) продолжают читать `TechLevel` без изменений.
- **Сменить движок**: вместо `PtuProgress += rate` → `Planet.ResearchPoints[cat] += rate`,
  с накоплением на изобретения. ПТУ становится **производной метрикой** от завершённых
  изобретений.
- **Скрытность**: система не имеет UI, игрок не выбирает направление, не видит прогресс.
  Только косвенные сигналы — новости, новые товары/оборудование, изменения цен.
- **Влияние на геймплей**: каждое изобретение — это конкретное изменение мира
  (новый item-шаблон, модификатор событий, разблокированная диалоговая ветка).

---

## 2. ПТУ и ГТУ — что меняется, что нет

### Не меняется
- ПТУ — байт 1..10 на каждой планете.
- ГТУ — байт 1..10 в `GalaxyData`.
- Формула расчёта ГТУ из ПТУ планет (текущая, `CalculateGtu`) — сохраняем.
- Внешние потребители читают `planet.TechLevel` как и сейчас.

### Меняется
- `PtuProgress` (float 0..100) **удаляется**. На замену — `Planet.ResearchPoints[cat] : Dictionary<string, float>`.
- ПТУ растёт **не от времени**, а от количества изобретений, в которые планета внесла
  заметный вклад (см. §8).
- Появляется новый файл состояния галактики: `GalacticResearchState` — глобальный
  пул прогресса по всем изобретениям + список завершённых.

## 3. Категории науки

Не путать с invention-категориями SR2 (там было 20, грубо «по типу оборудования»). У нас —
**семантические научные дисциплины**, 7 штук. Каждое изобретение требует поинты в одной
или нескольких дисциплинах.

| Категория | Что покрывает |
|---|---|
| `Medicine` | Лекарства, генетика, продление жизни, борьба с эпидемиями |
| `Materials` | Сплавы, броня, обшивка, корпуса |
| `Propulsion` | Двигатели, гиперпрыжок, топливо |
| `Weapons` | Стволы, ракеты, энергетика боевая |
| `Computing` | ИИ-системы, радары, сканеры, навигация |
| `BioTech` | Терраформирование, биотопливо, экосистемы |
| `Energy` | Реакторы, защитные генераторы, накопители |

Расширяемо через `Assets/Config/science_categories.json`.

## 4. Производство research points на планете

Каждый ход (`PlanetaryTechSystem.TickAll`) для каждой обитаемой планеты:

```
for each category C in ScienceCategories:
    rate_C = BasePerCapita
           * Population
           * RaceBias[Race, C]                  // 0.5..2.0
           * EconomyBias[Economy, C]            // 0.5..2.0
           * GovBias[Gov, C]                    // 0.5..2.0
           * PTU_Multiplier                     // 1.0 + 0.15*(PTU-1)
           * EventMultiplier(planet, C)         // эпидемия гасит Medicine? нет — наоборот, стимулирует
           * MoodGate(planet, C)                // 0 или 1 (см. §5)

    planet.ResearchPoints[C] += rate_C
```

Параметры все в `Assets/Config/science_production.json`:
- `BasePerCapita: float` — базовая ставка (тюнится так чтобы поздняя игра давала ~1
  изобретение/месяц галактики).
- `RaceBias: Dictionary<Race, Dictionary<Category, float>>` — например, Гаалы:
  `Computing=1.5, BioTech=1.4, Weapons=0.7`; Маалок: `Weapons=1.6, Materials=1.2, Medicine=0.6`.
- `EconomyBias: Dictionary<EconomyType, Dictionary<Category, float>>`.
- `GovBias: Dictionary<Government, Dictionary<Category, float>>`.

После накопления, `ResearchPoints[C]` тратятся при «фиксации вклада» в изобретения
(см. §7).

## 5. Mood — скрытый ограничитель

Импортируем из SR2 идею «социального капитала», переименовываем в
**`Planet.SocialCapital` (float 0..100)**.

**Зачем**: создаёт неравномерность прогресса. Планета не «капает поинты как часы», а
накапливает социальный капитал, в момент готовности — рывок исследований. После рывка
капитал падает, планета «отдыхает».

**Поведение**:
- Растёт каждый ход на `MoodDelta` (расово-зависимая константа, 0.3..1.0).
- Падает при катастрофах: −20 при войне в системе, −30 при оккупации, −10 при потере
  PTU, −15 при революции, −5 при эпидемии.
- Гейтит «дорогие» исследования: чтобы изобретение тира T могло принять поинты на этой
  планете, нужно `SocialCapital >= T * 8`. То есть тир 10 требует SocialCapital >= 80.
- При успешной фиксации вклада планетой: SocialCapital −= 5 * вкладtier. То есть рывок
  на изобретении тира 8 стоит планете 40 капитала.

Игрок не видит SocialCapital. Видит только: «эта планета 30 ходов ничего нового не
произвела» (она копит) → «вдруг куча новостей о технологическом прорыве» (она тратит).

## 6. Изобретения (InventionNode)

`Assets/Config/inventions.json`:

```json
{
  "AntibioticGen3": {
    "Tier": 4,
    "DisplayName": "Антибиотики 3-го поколения",
    "Cost": { "Medicine": 800, "BioTech": 200 },
    "Prerequisites": ["AntibioticGen2"],
    "Effects": [
      { "Type": "ModifyEventChance", "EventId": "Epidemic", "Multiplier": 0.4 },
      { "Type": "AddGood", "GoodId": "MedKitAdvanced", "BasePrice": 250 },
      { "Type": "TriggerNews", "NewsKey": "Inventions.AntibioticGen3" }
    ]
  },
  "ImprovedReactor": {
    "Tier": 6,
    "DisplayName": "Микротермоядерный реактор",
    "Cost": { "Energy": 1500, "Materials": 500 },
    "Prerequisites": ["FusionStable"],
    "Effects": [
      { "Type": "AddItemTemplate", "TemplateId": "Engine_Fusion_MkII",
        "SpawnWeight": 0.4, "MinTL": 5 },
      { "Type": "RemoveItemTemplate", "TemplateId": "Engine_Plasma_MkI",
        "SpawnWeight": 0.0 },
      { "Type": "TriggerNews", "NewsKey": "Inventions.ImprovedReactor" }
    ]
  }
}
```

### Поля

- `Tier: int 1..10` — задаёт «потолок» доступности (исследовать может только планета с
  PTU ≥ Tier−1).
- `Cost: Dictionary<Category, int>` — сколько суммарно поинтов нужно из коалиции.
- `Prerequisites: string[]` — другие изобретения, которые должны быть открыты.
- `Effects: UnlockEffect[]` — что меняется в мире при разблокировке (типы — §10).

### Размер контента

Начинаем с **~30 изобретений** (5 категорий × 6 тиров грубо), это достаточно для
демонстрации концепции и пары игровых лет. В целевом контенте — ~100–150 узлов.

## 7. Пул прогресса — гибридный

Большинство изобретений (~80%) исследуются **общегалактически коалицией**. Часть
(~20%) помечены как **расовые** — прогресс по ним идёт только от планет соответствующей
расы, и эффекты доступны только этой расе.

### Поле `Race` в InventionNode

```json
"GaalianQuantumComputer": {
  "Tier": 7,
  "Race": "Gaalian",                // ← если указано — расовое
  "Cost": { "Computing": 1500, "Energy": 400 },
  ...
}
```

- Если `Race` не указано (или `null`) — общегалактическое изобретение, пул общий.
- Если `Race = "Faean"` — только faean-планеты вносят вклад, при разблокировке
  эффект доступен только faean-сущностям. Например, `AddItemTemplate` с
  `OwnerFilter = "Faean"` — новый шаблон оружия попадает в магазины **только**
  faean-планет.

### Идеи расовых изобретений (контент)

- `Gaalian` — Computing+: квантовые ИИ, продвинутые радары, эксклюзивные сканеры.
- `Faean` — BioTech+: биотопливо, генетические апгрейды, эксклюзивные защитные генераторы.
- `Maloc` — Weapons+: тяжёлые орудия, ракетные системы, эксклюзивные ББ-боеприпасы.
- `Peleng` — Materials+: контрабандные модификации, маскировка, эксклюзивные корпуса для контрабанды.
- `People` — Universal+: универсальный профиль, эксклюзивные «оптимизированные» версии стандартного оборудования.

Каждое накопление `ResearchPoints[C]` на планете автоматически распределяется по
**активным изобретениям**, в стоимости которых есть категория C — с учётом расового
фильтра.

```
GalacticResearchState:
    Completed: HashSet<string>             // ids открытых
    Active:    Dictionary<string, InventionProgress>
        // id → { Spent[cat]: float, Contributors[planetUid]: float }
```

### Алгоритм распределения

Раз в `N` ходов (например, 7 — синхронно с обновлением магазина оборудования):

```
for each planet P in coalition:
    for each category C in P.ResearchPoints:
        points = P.ResearchPoints[C]
        candidates = Active inventions where:
            - C ∈ invention.Cost
            - invention.Tier ≤ P.PTU + 1
            - P.SocialCapital >= invention.Tier * 8
            - invention.Race is null OR invention.Race == P.Race    // расовый фильтр
        if not candidates: continue
        share = points / candidates.Count          // равномерно по умолчанию
        for each inv in candidates:
            needed = inv.Cost[C] - inv.Spent[C]
            applied = min(share, needed)
            inv.Spent[C] += applied
            inv.Contributors[P.Uid] += applied
            P.ResearchPoints[C] -= applied
            P.SocialCapital -= 5 * (inv.Tier / 10.0)

# Проверяем завершение
for each (id, inv) in Active:
    if all categories satisfied (Spent[c] >= Cost[c]):
        UnlockInvention(id)                          // см. §10

# Активируем новые узлы, чьи prerequisites выполнены
for each inv in Locked:
    if inv.Prerequisites ⊆ Completed and inv not in Active:
        Active[inv.id] = new InventionProgress()
```

**Особый случай — крупный спонсор**: если одна планета внесла ≥ 40% поинтов в
изобретение, она помечается как **главный контрибьютор**. Эффект только для §8 (расчёт
ПТУ): главный контрибьютор получает +1 «зачёт» в свой пул.

## 8. Расчёт ПТУ из изобретений

ПТУ остаётся 1..10. Новая формула, заменяющая «таймер»:

```
foreach planet P:
    credits = count(inventions where P was MainContributor)
    P.TechLevel = clamp(1 + floor(credits / N_per_level), 1, 10)
```

Где `N_per_level` — константа («чтобы поднять PTU на 1, нужно быть главным
контрибьютором N изобретений своего текущего тира»). Тюнится так чтобы PTU 5 достигался
к ~50 игровым годам у топовых планет, PTU 8 — к ~150, PTU 10 — крайне редко.

**Альтернатива (для обсуждения)**: ПТУ растёт **строго от тира изобретений**:
```
P.TechLevel = max(invention.Tier for invention where P was MainContributor)
```
Это даёт чистый «уровень = максимальный достигнутый» — простой и понятный, но менее
гладкий.

**Дефолт в доке — первый вариант** (count-based), как более устойчивый к случайностям.

---

## 9. Расчёт ГТУ (без изменений)

`PlanetaryTechSystem.CalculateGtu` остаётся как есть: максимальный уровень L такой, что
≥ K планет коалиции имеют `PTU >= L`. K берётся из `GtuConfig.Levels`.

Так как PTU теперь движется медленнее и неравномернее (большинство планет застрянут на
PTU 3–5), ГТУ органично будет ниже первые десятки лет и расти по мере «технологического
прорыва» отдельных научных центров.

## 10. UnlockEffects — что делают изобретения

Visitor-pattern на интерфейсе `IUnlockEffect.Apply(GalaxyData, GalaxyConfig)`. Дефолтный
набор:

| Тип | Эффект |
|---|---|
| `AddItemTemplate` | Добавить новый шаблон оборудования в пул генерации `ItemFactory`. Параметры: `TemplateId, SpawnWeight, MinTL, MaxTL, OwnerFilter` (для расовых изобретений — авто-заполняется расой узла). |
| `RemoveItemTemplate` | Понизить/обнулить `SpawnWeight` старого шаблона. Шаблон не удаляется (уже выпущенные предметы продолжают существовать), но в новые магазины он не попадает. |
| `AddGood` | Добавить новый товар в каталог торговли. |
| `RemoveGood` | Снять товар с производства (устаревание). |
| `ModifyEventChance` | Множитель к вероятности срабатывания события (эпидемия, бунт, и т.д.). |
| `ModifyPlanetParam` | Глобальный модификатор параметра планеты (например, +5% Population growth). |
| `UnlockDialogBranch` | Открыть новую ветку диалогов (требует поддержки в `DialogService`). |
| `TriggerNews` | Послать новость в `GameConsole` / news feed. Шаблон в `Assets/Config/news_templates.json`. |
| `ModifyGoodPrice` | Глобальный множитель цены товара (открытие нового лекарства давит цены старых). |
| `EnableInvention` | Принудительно разблокировать другое изобретение (обходя его cost) — для квестовых веток. |

Список расширяется по необходимости через добавление нового `IUnlockEffect`.

## 11. Влияние на магазин оборудования

При генерации предмета в магазине (`EquipmentShopSystem.TickWeekly` — отдельный
диздок/пункт 3) фабрика берёт шаблон **из активного пула** для текущего ГТУ. После
изобретения нового двигателя:
- Старый шаблон сохраняется, но имеет малый `SpawnWeight` → редко появляется.
- Новый шаблон — основной для планет с PTU ≥ MinTL.

Это даёт игроку **наблюдаемый эффект**: на молодых планетах с низким ПТУ ещё долго
продаётся старый Engine_Plasma_MkI, а на топовых — уже Engine_Fusion_MkII. Через 20 лет
старый практически исчезает.

## 12. Влияние на товарный рынок

### 12.1 Через изобретения
- `AddGood` — новый товар появляется в каталоге. Сначала продаётся только на планетах
  с PTU ≥ Tier изобретения (производит ограниченное число планет). Со временем спрос
  расходится по галактике.
- `ModifyGoodPrice` — открытие «биотоплива» давит цену «топливо» × 0.7 галактически.
- Эпидемические события через `ModifyEventChance` напрямую трогают рынок: меньше
  эпидемий → меньше Decay-всплесков цен медикаментов.

### 12.2 Архитектура товарной экономики планеты (важное уточнение)

Из обсуждения с пользователем — товарная экономика планеты строится в **два слоя**:

**Слой 1: внутреннее производство/потребление (база).**
Каждая планета имеет встроенный per-good `ProductionDelta` (единиц/ход) — определяется
её EconomyType и Race. Примеры:
- Аграрная (`EconomyType = "Agricultural"`): Food +5/ход, Alcohol +3/ход, Medicine −1/ход.
- Индустриальная: Equipment +3/ход, Minerals −2/ход, Food −1/ход.
- Смешанная: всё ±1/ход.
- Раса добавляет модификаторы (Faean: BioGoods +1, Maloc: Weapons +1).

Этот поток применяется каждый ход в `TradeSystem.TickDaily` ДО дрейфа цен. В равновесии
без NPC-торговли аграрная планета постоянно завалена дешёвой едой, индустриальная — дорогим
оружием, и обе нуждаются в обмене.

**Слой 2: NPC-транспорты как реальный обмен между планетами.**
Транспорты живут отдельно — `NpcTransportTrader` AI. Каждый рейс:
1. Сидит на планете → перебирает goods с положительным `Stock - BasePrice * threshold`
   (избыток + дешевизна).
2. Сканирует 3–5 ближайших систем (по `ConnectedStarUids`) → для каждой планеты
   запрашивает `BuyPrice` всех goods.
3. Выбирает пару (купить здесь good X, продать там) с максимальной маржой ≥ X% после
   расходов на топливо.
4. Покупает (вычитает реальный сток у планеты-источника, переводит ей деньги).
5. Летит, при прибытии — продаёт (добавляет реальный сток планете-цели, забирает деньги).
6. Берёт новый рейс.

**Эффект**: галактика становится живой. Аграрная планета постоянно отгружает еду на
индустриальную, индустриальная отгружает оборудование. Цены на обеих стабилизируются на
средне-галактическом уровне (там где есть транспортный поток) и далёкие/изолированные
планеты остаются с экстремальными ценами (там где транспортов мало) — игрок получает
естественный мотив для торгового маршрута. Прерывание потока (война, клинги) → цены
расходятся → возможности для игрока.

Это **отдельный документ** (`docs/npc_trade_simulation.md`) — здесь упоминаем для
полноты картины. Связь с научной системой: новые товары через `AddGood` сразу попадают
в pool, который оценивают транспорты — спрос на них растёт органически.

## 13. Видимость для игрока

Прямого UI **нет**. Игрок видит:

1. **Новости** (через `TriggerNews`): «Учёные Гаалии-2 завершили работы над
   "Антибиотиками 3-го поколения". Ожидается снижение эпидемических рисков и выход на
   рынок новых медицинских препаратов.»
2. **Появление новых товаров/оборудования в магазинах** (косвенно).
3. **Изменение цен** (косвенно).
4. **Изменение частоты событий** (со временем замечается, что эпидемий стало меньше).
5. **Возможный кодекс/энциклопедия** (опционально, поздний UI): список «известных
   технологий галактики» с датами открытия. Чисто lore-readable, без чисел/прогресса.

Не показывается:
- Где какое исследование, на сколько процентов;
- Какая планета какой вклад внесла;
- SocialCapital, ResearchPoints, contributors.

## 14. Деградация и потери

| Сценарий | Что происходит |
|---|---|
| Планета захвачена клингами (Owner=Klings) | Планета выпадает из коалиционного пула. Завершённые изобретения остаются глобально (знания распространились). Активный вклад через неё прерывается. |
| Планета возвращена коалиции | Заново включается в пул. ПТУ начинает с того уровня, на котором был при потере. |
| Планета уничтожена | То же что выше, безвозвратно. Если она была единственным контрибьютором активного изобретения — прогресс этого изобретения сбрасывается до 0. |
| Революция (смена Gov) | ПТУ −1 (одноразово), SocialCapital −15, активный прогресс по «социальным» категориям (Medicine, BioTech) теряет 30% — общество в смятении. |

Знания **не теряются** на уровне галактики — только локальный прогресс. Это
консервативно (предотвращает frustrating потери) и реалистично (распространение знаний
после первой публикации необратимо).

## 17. Открытые вопросы

### Решённые (зафиксированы выше)
- ✅ **Гибридный пул**: ~80% общегалактических узлов + ~20% расовых (см. §7).
- ✅ **Игрок не катализатор** — чистый наблюдатель.
- ✅ **Клинги/пираты не крадут** технологии.
- ✅ **NPC-транспорты полноценно симулируются** с реальным грузом, ищут маржу в 3–5
  ближайших системах (см. §12.2; отдельный диздок).

### Открытые

1. **ПТУ — count vs max tier.** Дефолт — `PTU = floor(credits / N_per_level)`.
   Альтернатива — `PTU = max(invention.Tier where MainContributor)`. Вторая проще, но
   менее гладкая (планета прыгает PTU 5 → 8 после одного крупного изобретения).

2. **Сколько узлов изобретений в финале.** Дефолт — 100–150. Меньше — игра пресная;
   больше — контент-долг.

3. **Item-шаблоны — добавление или замена.** Дефолт — оба варианта поддерживаются
   (`AddItemTemplate` / `RemoveItemTemplate`). Открыт вопрос — должен ли каждый
   `AddItemTemplate` **автоматически** понижать `SpawnWeight` похожих старых шаблонов
   (через тег «семейства» — engine, weapon, hull), или это всегда явное решение
   per-invention в конфиге.

4. **Детерминизм между играми.** Дефолт — все изобретения с одинаковым cost/effects в
   каждой игре. Альтернатива — рандомизация: в каждой игре часть узлов получает
   небольшую вариацию (cost ±20%, иногда эффект чуть другой). Даёт реиграбельность,
   усложняет балансировку.

5. **Encyclopedia/codex для игрока.** Дефолт — не делаем, только новости. Альтернатива —
   позднее добавить read-only UI «известные технологии галактики» (без чисел,
   только список с датами и описанием). Полезно для лора, не критично для геймплея.

6. **Скорость симуляции на больших галактиках.** При 200 планетах × 7 категорий каждый
   ход = 1400 счётчиков обновляются + распределение по N активных изобретений.
   Архитектурно дёшево, но проверить bench. Если медленно — распределение делать раз
   в 7 ходов (как уже заложено), а не каждый.

7. **Mood/SocialCapital для расовых изобретений.** Расовое изобретение тира T на планете
   расы R — кто гейтит? Только faean-планеты могут вносить в Faean-узлы, значит и
   SocialCapital считается только их. Если у всех faean-планет SocialCapital низкий,
   их единственное расовое изобретение надолго замирает. Это OK (расы по-разному
   стабильны) или нужен fallback?

8. **Революция как триггер ПТУ-падения.** В §14 — «Революция: ПТУ −1». Это разумно?
   Альтернатива: PTU не падает, но активный прогресс по социальным категориям теряется
   (мягче). Зависит от того, насколько часто революции случаются в твоей балансировке.
