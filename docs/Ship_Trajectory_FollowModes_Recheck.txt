§2. ИСПРАВЛЕНИЕ — Order == 2 (FOLLOW_OBJ): TPlanet-цель

Эта ветка — внутри switch (case 2), после фильтра «не TShip».

Параметры:
  planet := AsClass(ship.DestObj, TPlanet)
  R_app  := planet.OrbitRadius + 150     // approach zone (planet[80] dword = OrbitRadius)
  R_land := planet.OrbitRadius + 50      // landing zone
  star_day_frames := ship.CurStar[+260]  // см. ниже

  ВАЖНО: ship.CurStar[+260] — это **число кадров в одном ходе для текущей
  звезды** (= a4 ≈ 200; внутри функции используется как «дней в будущее»
  для расчёта будущей орбиты планеты).

────────────────────────────────────────────────────────────────────────────────
2.1  ПЛЕЕР (ship == Player)
────────────────────────────────────────────────────────────────────────────────
Алгоритм:

  future_pp := PlanetFutureOrbitPos(planet, star_day_frames)
                 // позиция планеты на её орбите через ход
  target    := future_pp + ship.DestPos          // ★ DestPos — offset от планеты
                 // (sub_45EDAC = ADD)

  cur_pp    := PlanetCurrentOrbitPos(planet)
  d²_now    := Dist²(ship.Pos, cur_pp)

  if d²_now > R_app²:                            // ship ВНЕ approach zone
      d²_target := Dist²(target, future_pp)
      if d²_target ≤ R_land²:                    // ★ target БЛИЗКО к будущей планете
          // Нужно «не въехать» в посадочную зону, найти ближайшую точку
          // на луче (ship.Pos → target), которая ОСТАЁТСЯ снаружи R_land.

          dist_full   := Dist(target, ship.Pos)
          dir_angle   := Atan2_PointToPoint(ship.Pos, target)
                                 // sub_871A50 = направление от ship к target
          unit_angle  := normalize_360(dir_angle)
          sin_a, cos_a — стандартные тригонометрии этого угла

          // === ШАГ 1: GREEDY HALVING ===
          step := dist_full
          loop:
              step := step * 0.5
              candidate := ship.Pos + dir * step  // дистанция от ship по dir
              future_pp := PlanetFutureOrbitPos(planet, star_day_frames)
              d²_candidate := Dist²(candidate, future_pp)
              if d²_candidate < R_land²  AND  step > 30:
                  continue
              else:
                  break

          // === ШАГ 2: БИНАРНЫЙ ПОИСК (точность 10) ===
          hi := step * 2.0   // последняя «inside R_land» точка
          lo := step          // последняя «outside R_land» точка
          while hi - lo > 10:
              mid := (hi + lo) * 0.5
              candidate := ship.Pos + dir * mid
              future_pp := PlanetFutureOrbitPos(planet, star_day_frames)
              if Dist²(candidate, future_pp) ≤ R_land²:
                  hi := mid
              else:
                  lo := mid

          step  := lo                            // КЛЮЧЕВОЕ: берём LO (вне зоны!)
          target := ship.Pos + dir * step        // финальная цель

          // Если шаги 1+2 не сработали, target остаётся = future_pp + DestPos
      // else: target = future_pp + DestPos, без корректировки

  else: // ship внутри approach zone — target тоже = future_pp + DestPos

  if ship.Pos != target:
      PushDestination(ship, target, day_step)
  return

Намерение: при подходе к планете игрок целится в точку (future_planet + offset).
Если эта точка оказалась внутри посадочной зоны будущей планеты
(а планета успеет туда переместиться), бинарный поиск находит точку
ближе к ship — но всё ещё вне R_land. Тем самым корабль «зависает»
снаружи посадочной зоны, не пытается влетать в планету.

ЧТО БЫЛО НЕ ТАК (прошлый отчёт):
  • Я писал про «бинарный поиск точки посадки», подразумевая что
    игрок ищет идеальную точку посадки на орбите.
  • На самом деле обратная задача — найти точку, которая ОСТАЁТСЯ ВНЕ
    landing-зоны (чтобы не врезаться).
  • Это работает только для случая «approach» (далеко от планеты).
    Когда игрок уже у планеты — никакой корректировки нет, target = future + offset.

Алгоритм проще:

  future_pp := PlanetFutureOrbitPos(planet, star_day_frames)

Алгоритм:

  follow_radius := TShip.CalcFollowRadius(ship)   // см. §0
                  // ★ зависит от ship.OrderData[low byte]: 0=auto, 1=close, 2=far

  if leader.RouteFilm.head:                       // у leader есть waypoints

                       follow_radius,          // дистанция позади
                       ref_node.angle)         // base_angle = курс leader’а

                   leader.Pos,

                   // leader.Angle = leader[+0x420] = double @ index 132

  PushDestination(ship, target, day_step)

  if ship.RouteFilm.tail:

      ship.DestPos.y := ship.RouteFilm.tail.pos.y

  • Я писал что «target = leader.RouteFilm.Tail.pos с фокусом» или
    «target = leader.Pos + смещение по угло+seed».
  • Точная формула: всегда **Dist2_0** = «точка позади ref-точки на

TPlanet — структуры для расчёта орбиты:
  +0x18 (24)  TStar*   parent_star
  +0x20 (32)  double   CurrentOrbitAngle (степени)
  +0x28 (40)  double   OrbitRadius
  +0x40 (64)  double   OrbitalSpeed (степень/кадр)
  +0x50 (80)  int      "size" / "OrbitRadius_int" (используется как
                       planet[80] для approach_zone = +150, landing = +50)
                       ★ ВНИМАНИЕ: в формуле бинпоиска NPC используется
                       planet[80] (int), а в orbit-расчёте planet[+0x28] (double).
                       Это разные представления одного и того же радиуса.

TStar — что важно для траекторий:
  +0x05C       float    PlanetAvoidRadius (используется в PlanPath)
  +0x104 (260) int      DayFrames           ★ = 200 кадров в одном ходе
  +0x108 (264) double   TimeFactor          ★ поправка для скорости

TShip — что используется в FOLLOW:
  +0x424 (1060) — байт-флаги внутри double Angle
                  (HIBYTE @ +0x423 = IsVisibleOnFilm — см. предыдущий отчёт)
  +0x42C (1068) uint32  OrderData
        - low byte (mask 0xFF): для FOLLOW_SHIP — режим CalcFollowRadius
                                для JUMP_HOLE  — флаг «через какую сторону дыры»
                                                  (HIWORD выбирает Pos1/Pos2)
        - == 0xFFFF0000:        для JUMP_HOLE «не использовать дыру»
                                для GenerateSpline — флаг половинной скорости

§6. КЛЮЧЕВЫЕ ВЫВОДЫ ПО ПЕРЕПРОВЕРКЕ
================================================================================
  1. DestPos для FOLLOW_OBJ (Order==2) — это **смещение** от target.Pos.
     Это критично для UI: клик на объект → DestPos := (0,0).
     Команда «лети рядом» с другого UI должна записать сюда конкретный
     offset, не абсолютную координату.

  2. Для игрока подход к планете включает **avoidance**, а не «landing
     poin search». Алгоритм гарантирует что выбранная цель НЕ внутри
     посадочной зоны будущей позиции планеты — корабль остановится
     снаружи.

  3. NPC заходят на планету «по дуге» с jitter относительно линии
     «планета → корабль», и используют **будущую** позицию планеты как
     центр расчёта. Это даёт реалистичный «упреждающий» полёт.

  4. FOLLOW_SHIP имеет три **тактических режима** через OrderData_low_byte
     (0/1/2), которые меняют дистанцию следования. Это, скорее всего,
     UI-настройка партнёра/wingman’а через диалог Talk_Partner_*.

  5. **TShip_UpdateEngine оказалось переименован**: реальное имя
     CalcFollowRadius, и используется ТОЛЬКО для FOLLOW_SHIP. Если
     где-то Order != 6 — функция кидает исключение.

  6. У всех Follow-веток есть общий паттерн: после PushDestination
     обязательно обновляется ship.DestPos = последний waypoint
     собственной плёнки. Это нужно для (а) корректной отрисовки
     UI «куда летит», (б) подсчёта оставшихся ходов в SE_ShipTurnBeforeEndOrder.

8.1  CalcFollowRadius СКАНИРУЕТ СВОИ ОРУЖИЯ, А НЕ ОРУЖИЯ LEADER'а
─────────────────────────────────────────────────────────────────────────────
В §0 (rev 2) и §3 я писал, что CalcFollowRadius перебирает оружие
LEADER'а (ship.DestObj). По дополнительной проверке декомпиляции
sub_710854 — это НЕВЕРНО.

Реальный код (a1 = ship, который следует):
    *(_BYTE *)(a1 + 300)              ← weapon_cnt    ★ SHIP'a
    *(_BYTE **)(a1 + 4*i + 276)       ← weapons[i]    ★ SHIP'a
    TShip_GetSpeed(a1, w)             ← active?       ★ SHIP'a
    TShip_WeaponEffectiveRange(a1,...)←               ★ SHIP'a

То есть **режим 1/2 учитывает оружие самого ship'а-ведомого**, а не leader'а.
Семантически это логично:
   • mode=1 (close-combat) — «держись на минимальной дальности
     МОЕГО оружия» → ведомый подходит так близко, чтобы стрелять
     даже короткоствольным.
   • mode=2 (long-range)   — «держись на МАКСИМАЛЬНОЙ дальности
     МОЕГО оружия» → ведомый отстаёт, чтобы успеть отойти.
В обоих случаях leader используется только как точка отсчёта.

8.2  FALLBACK В CalcFollowRadius
─────────────────────────────────────────────────────────────────────────────
В §0 (rev 2) формула фолбэка была записана как
    TRUNC(leader[+0x45C] + leader.weapons[279]) + 15

Реальная формула (a1=ship, leader=v13):
    TRUNC(ship[+0x45C]/*float*/ + leader[+0x45C]/*float*/) + 15

Поле +0x45C — это hull/collision_size (или similar). То есть фолбэк
устанавливает дистанцию следования = сумма «размеров» обоих кораблей +
15 единиц зазора. Это «collision-avoidance default» когда ни одно
оружие не активно.
