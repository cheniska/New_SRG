# Сохранения

Модули: `Simulation/SaveSerializer.cs` (формат, версии, миграции), `Utils/SaveTypeBinder.cs`
(разрешённые типы), `Core/GalaxySaveManager.cs` (файл), `Simulation/SimulationSession.LoadFrom`
(восстановление мира).

---

## Формат

JSON (Newtonsoft) — объект `SaveData`:

```json
{
  "Version": 2,
  "ActiveKey": "MilkyWay",
  "Galaxies": { "MilkyWay": { ...GalaxyData... }, "Andromeda": { ... } },
  "RngState": [123, 456, 789, 1011]
}
```

- `TypeNameHandling.Auto`: полиморфные поля (`Directive` и т.п.) пишут `$type`.
- `SaveTypeBinder` разрешает создавать из `$type` только SRG-типы сборки `SRG.Simulation`,
  примитивы, строки, Unity-векторы/цвета и стандартные коллекции из них — сейв от другого
  игрока не может инстанцировать произвольный тип .NET.
- Старые имена типов (`"X, Assembly-CSharp"`, типы без namespace) разрешаются binder'ом.

## Версии и миграции

| Версия | Формат |
|---|---|
| 0 | корень — один `GalaxyData` (до мультигалактики) |
| 1 | контейнер `{ ActiveKey, Galaxies }` без поля `Version` |
| 2 | + `Version`, `RngState`; типы в сборке `SRG.Simulation` |

Миграции работают над JSON-деревом до десериализации, шаг `i` переводит версию `i` в `i + 1`.
Сейв новее игры или повреждённый файл отвергаются с `InvalidSaveException`.

**Как изменить формат:** увеличить `SaveSerializer.CurrentVersion`, добавить шаг в `Migrations`,
добавить тест в `SaveFormatTests` на чтение сейва предыдущей версии.

## Запись

`GalaxySaveManager` пишет во временный файл и заменяет им сейв (`File.Replace`): сбой посреди
записи не портит прежнее сохранение, предыдущее остаётся в `galaxy_save.json.bak`.

## Схема формата (вместо отдельных DTO)

Модели мира сериализуются напрямую. Чтобы формат не менялся незаметно при рефакторинге моделей,
он зафиксирован в `Assets/Tests/EditMode/SaveSchema.txt` — все типы и поля, попадающие в JSON
(строится `SaveSchema.Describe()` по тому же контракту, что и сейв, включая полиморфных наследников
`Directive`/`NpcAction`/`NpcOrder`). Тест `SaveSchemaTests` сверяет схему с кодом.

Если тест упал:
1. Посмотреть в сообщении, что удалено/добавлено. Переименование поля или смена типа ломают чтение
   старых сейвов → увеличить `SaveSerializer.CurrentVersion` и добавить миграцию. Новое поле обычно
   безопасно (в старом сейве будет значение по умолчанию).
2. Обновить эталон: `SRG_UPDATE_SAVE_SCHEMA=1 dotnet test tools/headless-tests` (или тот же флаг при
   запуске Unity Test Runner) и закоммитить `SaveSchema.txt` вместе с кодом.

Почему не DTO: зеркальная копия ~30 классов моделей с маппингом в обе стороны — тысячи строк
дублирования на каждое изменение модели. Схема даёт главное, что дали бы DTO (формат меняется
только осознанно и с миграцией), без этой цены.

## Что сохраняется, а что восстанавливается

| Данные | Как |
|---|---|
| Галактики, звёзды, планеты (включая текущие углы орбит), корабли, инвентарь, новости, директивы, состояния генштабов, наука | в JSON |
| Состояние ИИ: `NpcBrain` (активность, директива, страх), вложенные `NpcAction`/`NpcOrder` | в JSON через `AiStateContractResolver`: все поля экземпляра, объект создаётся без конструктора |
| Маршрут и курс корабля, последний агрессор, кулдауны, форсаж, цель ручной стрельбы, активные боевые эффекты | в JSON |
| Характер NPC (`ShipData.Personality`) | в JSON; мозг связывается с ним после загрузки |
| Курсор анализа присутствия и история объявлений | в JSON (`GalaxyData.PresenceCursor/PresenceLastPost`) |
| Состояние RNG | `RngState`, восстанавливается после десериализации |
| Индексы `StarsMap`/`PlanetsMap`, обратные ссылки | пересобираются в `SimulationSession.LoadFrom` |
| Счётчики кораблей для спавна/ИИ (`GalaxyData.ShipCounters`) | пересчитываются при загрузке (и ежедневно) |
| Счётчик Id новостей | вычисляется по максимальному Id (`GalaxyNewsService.SyncNextId`) |
| Кэши ИИ/поиска путей | сбрасываются при загрузке |
| Визуальные данные (`RenderPath`, кадры анимации, `LandingPhase`) | не сохраняются |

`Vector2` пишется компактно `{x, y}` (`Vector2JsonConverter`); старые сейвы с полями
`normalized/magnitude` читаются.

## Правила для нового кода

- Состояние, влияющее на игру, — в моделях (`GalaxyData`, `ShipData`, …), не в `static`.
- ИИ хранит ссылки на корабли/звёзды через UID; прямая ссылка — только кэш с `[NonSerialized]`
  (проверяется `AiStateSerializationTests`).
- Не выбирать случайный элемент по порядку обхода `Dictionary`/`HashSet`: после удалений порядок
  зависит от истории и не переживает сохранение — сначала отсортировать ключи.
- Справочные запросы к конфигу (`ItemsConfig.GetItem`) не расходуют случайность симуляции; разброс
  характеристик нового предмета — только через `GetItemForNewInstance`.

Всё это проверяет golden-тест `SaveLoad_ContinuesIdentically`: 5 ходов → сейв → 10 ходов даёт то же
состояние, что 15 ходов без сохранения.
