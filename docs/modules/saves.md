# Сохранения

Модули: `Simulation/SaveSerializer.cs` (формат, версии, миграции), `Utils/SaveTypeBinder.cs`
(разрешённые типы), `Core/GalaxySaveManager.cs` (файл), `Simulation/SimulationSession.LoadFrom`
(восстановление мира).

---

## Формат

JSON (Newtonsoft) — объект `SaveData`:

```json
{
  "Version": 2,
  "ActiveKey": "MilkyWay",
  "Galaxies": { "MilkyWay": { ...GalaxyData... }, "Andromeda": { ... } },
  "RngState": [123, 456, 789, 1011]
}
```

- `TypeNameHandling.Auto`: полиморфные поля (`Directive` и т.п.) пишут `$type`.
- `SaveTypeBinder` разрешает создавать из `$type` только SRG-типы сборки `SRG.Simulation`,
  примитивы, строки, Unity-векторы/цвета и стандартные коллекции из них — сейв от другого
  игрока не может инстанцировать произвольный тип .NET.
- Старые имена типов (`"X, Assembly-CSharp"`, типы без namespace) разрешаются binder'ом.

## Версии и миграции

| Версия | Формат |
|---|---|
| 0 | корень — один `GalaxyData` (до мультигалактики) |
| 1 | контейнер `{ ActiveKey, Galaxies }` без поля `Version` |
| 2 | + `Version`, `RngState`; типы в сборке `SRG.Simulation` |

Миграции работают над JSON-деревом до десериализации, шаг `i` переводит версию `i` в `i + 1`.
Сейв новее игры или повреждённый файл отвергаются с `InvalidSaveException`.

**Как изменить формат:** увеличить `SaveSerializer.CurrentVersion`, добавить шаг в `Migrations`,
добавить тест в `SaveFormatTests` на чтение сейва предыдущей версии.

## Запись

`GalaxySaveManager` пишет во временный файл и заменяет им сейв (`File.Replace`): сбой посреди
записи не портит прежнее сохранение, предыдущее остаётся в `galaxy_save.json.bak`.

## Что сохраняется, а что восстанавливается

| Данные | Как |
|---|---|
| Галактики, звёзды, планеты (включая текущие углы орбит), корабли, инвентарь, новости, директивы, состояния генштабов, наука | в JSON |
| Характер NPC (`ShipData.Personality`) | в JSON |
| Курсор анализа присутствия и история объявлений (`GalaxyData.PresenceCursor/PresenceLastPost`) | в JSON |
| Кулдаун сброса груза от страха (`ShipData.LastFearDropTurn`) | в JSON |
| Состояние RNG | `RngState`, восстанавливается после десериализации |
| Индексы `StarsMap`/`PlanetsMap`, обратные ссылки | пересобираются в `SimulationSession.LoadFrom` |
| Счётчик Id новостей | вычисляется по максимальному Id (`GalaxyNewsService.SyncNextId`) |
| Кэши ИИ/поиска путей | сбрасываются при загрузке |

## Известные ограничения

- **Текущее решение ИИ (`NpcBrain`) не сохраняется.** После загрузки NPC заново выбирают
  активность (характер при этом сохраняется). Поэтому тест
  `SaveLoad_ContinuesIdentically` помечен `Ignore`; `SaveLoad_RoundTrip_PreservesState`
  (состояние сразу после загрузки совпадает с сохранённым) — проходит.
  Чтобы снять ограничение, `NpcAction`/`NpcOrder` должны хранить ссылки на объекты мира
  через UID и сериализоваться (полиморфно, как директивы).
- Модели мира сериализуются напрямую (без отдельных DTO). Версии и миграции дают механизм
  менять формат, не ломая старые сейвы; выделение DTO — отдельная задача.
