# Вики New SRG на GitHub Pages

Стартовая страница: [index.html](../index.html). Статьи и ресурсы: [wiki/](../wiki/).

Сайт полностью статический: расовые статьи и справочники из GameDoc, поиск, ссылки, спойлеры с технической информацией и телефонная версия. Хостинг ChatGPT Sites больше не используется в качестве адреса проекта.

## Публикация

В настройках репозитория откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Workflow **Publish New SRG wiki** собирает только сайт и публикует его через GitHub Pages. После первого включения запустите workflow через Actions → Publish New SRG wiki → Run workflow, если автоматический запуск уже завершился ошибкой из-за выключенных Pages.

Ожидаемый адрес после успешной публикации: https://cheniska.github.io/New_SRG/

## Пересборка HTML

Из корня репозитория:

```bash
cd wiki-site
node export-github.mjs
```

Команда пересобирает корневой index.html и папку wiki/ из актуальных Markdown-статей GameDoc. После правок документов включайте изменившиеся HTML, оглавление, ресурсы и поисковый индекс в тот же коммит. Workflow собирает отдельный каталог `.pages` для развёртывания, но сам не изменяет файлы ветки `main`. Если Pages публикуется также из ветки, старые HTML могут перезаписать свежую публикацию. Проверка в workflow выявляет такое расхождение; итог проверяется по содержимому опубликованной страницы. Исходные досье остаются источником канона; в расовые статьи из общей истории добавлены их точки зрения и ссылки на объективное изложение.

Для независимого каталога публикации:

```bash
node export-github.mjs ../.pages
```

В папку публикации попадают только index.html, .nojekyll и wiki/; файлы Unity-проекта не публикуются. Сборщик использует включённый Marked с сохранённой лицензией и не требует установки пакетов.

Общие даты эпохи контактов хранятся в `GameDoc/data/chronology.json`. Перед пересборкой после изменения реестра: `python tools/docs/chronology.py sync`, затем `python tools/docs/lore_format.py index`. Проверка дат включена в публикацию.

## Интерактивный атлас Бореи

Атлас встроен в статью [грондаров](../wiki/race_grondary.html#borea-atlas), также доступен [отдельно](../wiki/borea-globe.html). Вращение, масштаб, переключение карт и сезонов работают без сторонних CDN и библиотек; используется сферическая проекция на WebGL с резервным Canvas-рендерером.

Исходные геоданные: `GameDoc/editorial/maps/borea/continents_draft.geojson`, `tectonics_draft.geojson` и `climate_draft.json` в том же каталоге. При сборке `build.mjs` формирует `borea-data.js` из этих файлов и переносит HTML, CSS и JS атласа в `dist/`; экспорт публикует их в `wiki/`. Новые карты следует добавлять как отдельные слои, используя общие координаты. Годовой обзор отображает объединённый ареал потенциального сезонного открытия морей; сезонные кадры — условные, не физическая симуляция. Текущие рабочие карты не заменяют каноническое досье.

### Природный облик и физическая карта

`borea-natural.js` воспроизводит детерминированное черновое поле высот, природные оптические текстуры и облачность из геоданных атласа; режимы «Вид из космоса», «Поверхность без атмосферы» и «Физическая карта» доступны в переключателе карты. В оптических режимах сезон влияет на снег и морской лёд. Атмосферный ореол рассчитывается на сфере отдельно, не входит в выгружаемую 2:1 развёртку; в варианте с атмосферой текстура включает облака. Без городов. Статические примеры лежат в `GameDoc/editorial/maps/borea/` (surface_texture.jpg, space_texture.jpg, relief_texture.jpg, borea_optical_preview.jpg). Скачать PNG текущего слоя можно через кнопку в атласе. Высоты и облачность — иллюстративные предложения, не утверждённые планетологические величины.

### Тепловые районы, высотные вершины и расселение

В `tectonics_draft.geojson` добавлены категории `high_peak` и `volcanic_arc`, у тепловых районов — IDs G01–G16, тип `oasis` или `industrial`, источник тепла. Шесть предложенных высоких вершин A1/A2, B1/B2, D1/D2 соответствуют локальной коллизии; точные отметки пока рабочие. Отдельный `settlements_draft.geojson` хранит представительные узлы U01–U28, их класс, связь с ресурсом тепла и предлагаемую функцию. При сборке оба слоя входят в `borea-data.js`. `borea-settlement.js` формирует относительную градацию плотности 0–100 на основе расстояний, климата, высот и условной геоактивности; цветовая шкала нелинейная, это не перепись. В атласе доступны отдельные карты геотермальных районов, городов и плотности. При нажатии на метку открывается описание; природные оптические слои не содержат городов. В `validation_draft.json` сохранены вычисленные диагностические значения, не канонические числа.

### Гидрография, города, дороги, день и ночь

`hydrology_transport_draft.geojson` содержит рабочие реки, притоки, кандидатов озёр и сухопутные коридоры. `borea-world.js` строит сезонную гидрографию, изображение дорог и городской дневной/ночной текстуры. `borea-natural.js` сохраняет природные оазисы в оптических текстурах и различает многолетние наземные ледники и сезонный снег. Дополнительная сеть `plate_extension` и метки P1–P4/J-* в тектонических данных задают предварительную замкнутую топологию; F — внутриплитный рифт. Все слои загружаются в общий `borea-data.js` при сборке. В атласе выбирается разрешение 1536×768 или 3072×1536; HD ощутимо тяжелее для мобильных устройств. PNG текущего слоя выгружается в выбранном разрешении. Образцы северного лета day_texture.jpg, night_texture.jpg, surface_texture.jpg, space_texture.jpg, relief_texture.jpg обновлены до 3072×1536; карты гидрографии и транспорта хранятся в редакционных материалах. Модель русел и наземных коридоров построена на синтетической карте высот, без утверждения точных условий водоснабжения и трасс.
